## 已确认的缺陷

校正后的透视相机要求观测点在相机前方，像素重投影误差小不能替代该物理条件。

- 本录制+34ms诊断中，1112个共同点有6个点在BA2解后出现负深度双目观察。最严重的点由约10米移动到约2931米，总chi2只从7.58变为12.51。
- `Optimizer::LocalInertialBA` 的单目分支已有 `isDepthPositive()`，双目分支却只判断chi2。惯性位姿优化的双目分支及其放宽残差救回分支也存在同类缺口。
- `FullInertialBA` 的结果延迟提交到地图。清理时不能将解后点坐标与解前关键帧位姿混用；必须在整批位姿/点提交完成后、持地图更新锁检查。
- 只补双目还不够：首版完整回放的BA2提交后仍有两个点、7条负深度单目观察。因此提交后的检查覆盖普通透视单目及双目观察。

这解释了一类极远、落在错误半空间却拥有低像素代价的地图点，不代表解释了所有正深度弱可观测点，也不等于解释全部历史跳变。

## 实现与上游差异

| 文件 | 修改 |
| --- | --- |
| `G2oTypes.h` | 为自定义 `EdgeStereo` / `EdgeStereoOnlyPose` 增加有限坐标、正相机深度判断；不改变投影公式、信息矩阵或顶点布局 |
| `Optimizer.cc` | 开关启用时补齐双目局部/位姿优化的正深度准入；救回分支不能把负深度观测再次救回 |
| `VioCheiralityGuard.h` | 对已提交地图的普通Pinhole观察检查深度；更新关键帧/地图点双向关联；所有观察无效时安全置坏；保留点刷新描述子、参考关键帧、法向和尺度距离缓存 |
| `LocalMapping.cc` | 全局惯性优化的位姿和点全部提交后、已有地图更新锁内执行检查 |
| `LoopClosing.cc` | GBA位姿和点全部提交后、已有地图更新锁内执行检查 |
| `System.cc` | 扫描导出先等待既有建图/闭环主线程，再持地图更新锁清理当前地图；发现非有限几何时拒绝导出，旧文件不由此覆盖 |
| 原生桥/Python | 增量能力 `cheirality_guard` 和可选计数器；旧库缺符号返回None；旧结构尺寸及Atlas格式不变 |
| 诊断 | 保存实际相机深度、透视/双目标识、真实观测视差及尺度信息；图边日志增加正深度标识 |

不引入距离、位移或点数门限，不改变噪声、IMU相位、恢复策略、鲁棒核或原始矩阵。正深度远点不会仅因距离远被删；这也不证明它的米制深度准确。

提交地图出现非有限世界坐标或相机坐标时触发既有粘性数值故障，后续位姿/导出拒绝，不能靠删除异常点掩盖数值损坏。
