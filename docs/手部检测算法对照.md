# MediaPipe 与 RTMPose-Hand 二维检测

## 使用

在工作配置的“检测”页选择 MediaPipe Hand 或 RTMPose-Hand，调整参数并点击“应用检测设置”。ROI 移到“区域”页、标定移到“标定”页；关节编号和极线显示移到“坐标”页。左右相机分别创建检测实例，在虚拟双目校正图上检测；手动 ROI 应用在同一校正图，输出恢复完整校正图坐标。当前默认仍为 MediaPipe。

RTMPose 需 `models/rtmdet_hand.onnx` 与 `models/rtmpose_hand.onnx`。两个模型来自 OpenMMLab 的官方 ONNX SDK，文件 SHA-256 见实验 provenance。项目现有环境已经安装 rtmlib 0.0.16 / onnxruntime 1.31.1。重建环境时先按项目原方式安装 numpy 与 opencv-contrib-python，再使用 `.venv\Scripts\python.exe -m pip install --no-deps -r requirements-rtmpose.txt`，避免另装不兼容版本的 opencv-python 覆盖既有环境。

## 算法与关键参数

MediaPipe Hand Landmarker 用掌部检测网络定位手，再将手部区域送入手部关键点网络；视频模式可用上一帧跟踪区域，跟踪失败时重新检测。程序另有全图无手时的固定重叠裁剪补救。参数为最大手数、掌部检测阈值、手部存在阈值和视频跟踪阈值。

RTMPose-Hand 使用 RTMDet-nano 检测手框，按框裁剪缩放到 256×256，再由 RTMPose-m 的 SimCC 坐标分类头预测 21 点；此实现逐帧重新检测，不使用 MediaPipe 视频跟踪或补救裁剪。可调最大手数、手框分数阈值和关节点分数阈值。RTMDet ONNX 中 NMS 已固化，因此不提供无效的 NMS 界面调节。空手框直接返回空结果，不调用 RTMPose 的全图回退。

两个模型的输出采用相同的腕、拇指、食指、中指、无名指、小指 21 点索引；正式比较只使用已有的官方 UmeTrack canonical20 映射，排除 MediaPipe 缺少对应定义的 CMC。语义近似并不意味着不同模型的标注定义完全一致。

当前 RTMPose 导出模型没有左右手分类或 MediaPipe 的局部 world landmarks，手侧为 Unknown、分数为 0，中性色显示；不猜测手侧。三维关联仍使用几何门控，左右手坐标卡及按左右标签匹配的 SHOW3D GT 误差不应被当作已有左右手识别。模型输出的二维分数也不是三维准确度或校准概率。

## 45 帧无 ROI 对照

对同一三个 HOT3D 官方训练片段各均匀抽 15 帧，全部为相同虚拟校正图，GT 只用于事后评分。MediaPipe 检测/存在阈值 0.2/0.5，开启当前零检出补救；RTMDet 手框阈值 0.3、关节阈值 0.3，不做额外裁剪；最多两手。注意两者阈值不等价，且一方使用补救，所以这是当前完整配置的实用对比，不是计算量完全相同的模型架构消融。

| 指标 | MediaPipe | RTMPose-Hand |
|---|---:|---:|
| 左图有输出帧 | 7/45 | 0/45 |
| 右图有输出帧 | 12/45 | 4/45 |
| 左右图均有输出帧 | 5/45 | 0/45 |
| 匹配投影 GT 的手 | 22/134 | 3/134 |
| 未匹配预测 | 0 | 1 |
| 可比较关节数 | 426 | 56 |
| 匹配关节平均像素误差 | 5.98 px | 3.98 px |
| 两视图平均检测耗时（本机本次） | 168 ms | 37 ms |

134 为有至少四个可投影点的 GT 手视图数；不是遮挡标注。只统计成功匹配且有效的关节，两个模型的比较点不是同一集合，因此不能因为 RTMPose 有效点平均误差较小就认定它整体更准确。未匹配预测不必然是误检。计时包括各自模型完整推理与 MediaPipe 的补救策略，不代表单网络速度。图像为单色第一人称场景且样本少，不能外推到彩色或其他相机。

逐帧 `records.json`、汇总 `summary.json` 和模型/数据 SHA-256 `provenance.json` 位于 `benchmark-results/mediapipe_vs_rtmpose_20261104/`。脚本 `scripts/compare_hand_detectors.py` 可复现，运行会覆盖该目录同名结果。评测不使用 GT 框，不补全未检测的手。
