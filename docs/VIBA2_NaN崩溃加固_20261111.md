# VIBA2 初始化 NaN 崩溃：加固与验证（2026-11-11）

## 1. 问题

`point_cond_20261111` 那次回放在第 984 帧**进程猝死**：

```
start VIBA 2
Sophus ensure failed in function 'Sophus::SO3<float,0>::expAndTheta', file so3.hpp, line 617.
SO3::exp failed! omega: -nan(ind) -nan(ind) -nan(ind)
```

`worker_exit_code = 3221226505`（`0xC0000409`）。这不是数组越界（诊断代码当次已正常写出 CSV），而是**把 NaN 喂给了 `Sophus::SO3f::exp`**，Sophus 在断言失败后抛出，进程直接终止。

- **概率性触发**：同命令重跑即通过；`stability_diagnostic` / `world_frame` 两个 DLL 同命令 1727 帧均 OK；4 次相关运行里仅 1 次崩。
- 与 `docs/VIO_CORE_NUMERICAL_AUDIT_20261111.md` 记录的上游风险同源（重力对齐/预积分在退化输入下产生 NaN）。
- 实机影响：长时间运行会随机崩在 VIBA2 初始化，GUI 只能看到连接中断（历史上 `WinError 10054` 一类现象）。

## 2. 根因定位

`NaN` 传播到 `SO3::exp` 的路径在 `ImuTypes.cc`：

```cpp
// 288  Preintegrated::GetDeltaRotation
return NormalizeRotation(dR * Sophus::SO3f::exp(JRg * dbg).matrix());
// 312  Preintegrated::GetUpdatedDeltaRotation
return NormalizeRotation(dR * Sophus::SO3f::exp(JRg*db.head(3)).matrix());
```

两处都把 `JRg * dbg`（陀螺偏置差经雅可比放大）**未做有限性检查**直接交给 `SO3::exp`。只要 `dbg` 或 `JRg` 含 NaN/极大值（VIBA1 偏置优化发散、reset 后残留偏置、零重力归一化等），就会命中这条路径。

## 3. 修复

新增 `third_party/ORB_SLAM3/include/VioSafeExp.h`：

```cpp
inline Eigen::Matrix3f VioSafeExp(const Eigen::Matrix3f& base, const Eigen::Vector3f& omega, bool* ok = nullptr);
```

- 有限且 `|omega|∞ ≤ 1e3` → 等价于 `base * exp(omega)`（与 `SO3::exp` 数值一致）；
- NaN / inf / 超大幅值 / `base` 非有限 → **不抛异常**，返回 `base` 原值，`ok=false`；
- 上层可据此判定该帧预积分失效，而不是让进程死掉。

`ImuTypes.cc` 两处改为：

```cpp
return NormalizeRotation(VioSafeExp(dR, JRg * dbg));
return NormalizeRotation(VioSafeExp(dR, JRg*db.head(3)));
```

保留了 `NormalizeRotation` 语义；对全部有限输入结果不变。

## 5. 局限

1. 只堵住 `SO3::exp` 这一条 NaN 出口；`GetDeltaVelocity`/`GetDeltaPosition` 仍可能传播 NaN（不崩溃，但会让该帧预积分无效）。若要彻底，应在 `Preintegrated` 层做统一的有效性标记。
2. 只是把"进程猝死"变成"该帧返回旧值 + ok=false"；**上层目前还没有消费 `ok`**（`GetDeltaRotation` 的返回值签名不含状态），所以 NaN 帧的语义仍是"沿用旧旋转"，需要后续在 `EdgeInertial`/初始化路径上显式判定。
3. 概率性触发意味着"跑通了"不能证明"永不崩"，只能证明该路径不再是猝死点。要证明根治，需在同一录制上重复 5 次以上且含人为注入 NaN 的用例。
4. 该 DLL 未接入实时链路（默认仍是 v9）；生效需设 `EGOHAND_VIO_LIBRARY` 并重启 GUI/live worker。
