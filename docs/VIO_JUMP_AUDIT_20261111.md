## 代码因果路径

1. `LocalMapping.cc:223` 进入 VIBA2，调用 `InitializeIMU(0.f,0.f,true)`。
2. `LocalMapping.cc:1293` 先优化重力、偏置等。双目情况下 `Optimizer.cc:3123` 固定尺度，不能把 VIBA2 前的双目位置统称为任意单目尺度。
3. `LocalMapping.cc:1337` 调用 `FullInertialBA(..., bFixLocal=false, ..., bInit=false)`。
4. `Optimizer.cc:423` 起添加关键帧位姿。位姿仅在 `bFixLocal` 分支中设置固定状态；当前全局调用未固定原点关键帧，且未添加世界位置先验。视觉与惯性相对约束不能观测整体平移，存在全局平移自由度。此问题提供了整体原点大幅漂移的可行机制。
5. `LocalMapping.cc:1392`、1419 把优化结果写回关键帧和地图点。`GetMapEpoch()` 将地图 ID、重置计数和大修改计数编码供上层分段。
6. `vio_panel.py:291` 收到 epoch 变化会清空旧轨迹，并对新轨迹重新适配视图。因此视觉上也可能出现整段轨迹突然换位置、缩放或朝向变化。

`live_quality.yaml` 当前 `pose_continuity:false`。此处没有启用显示重锚来掩盖跳变。

## 必要更正与下一步验证

- 双目由基线提供米制尺度。`inertial_scale_finalized` 当前实质上是 BA2 完成标志，不能作为“米制从无到有”或定位准确的证明。原生桥对此的旧注释不准确。
- 不能仅因 epoch 改变就宣称数百米跳变正常；必须验证新旧地图之间是否由统一刚体变换解释，以及相对几何是否保持。
- 要验证原点自由度假设，应记录 BA 前后同 ID 关键帧和地图点，拟合刚体变换并报告残差、相对距离、重投影误差和 IMU 残差；再在保留原版 DLL 的前提下对锚定全局自由度的版本做同输入 A/B。
- 同 epoch 的其他小跳变不能全部归于全局优化。当前日志缺少逐次局部 BA 的位姿修正量与残差，无法区分局部优化、弱纹理/双目匹配和标定/时序误差的贡献。
