# 远点绝对深度门限：5×2 对照结果（首次有可归因结论，2026-11-11）

配套：`docs/远点深度门限_首次对照_20261111.md`（首次无效对照）、`docs/地图点深度发散_根因链_20261111.md`（根因链）

## 1. 这次为什么能得出结论

前三次对照（`System.thFarPoints`、BA 后止血、门限首次）都失败在**无法确认机制是否生效**。这次补齐了两件事：

1. **拒绝计数器**：`VioDepthGate::Rejected()` → 导出 `egohand_vio_depth_gate_rejected()` → `poses.jsonl` 的 `optimization_counters.depth_gate_rejected`；
2. **5×2 重复**：同一 DLL、同一录制、同一帧数（1200），只切 `EGOHAND_VIO_DEPTH_GATE`。

ABI 安全性已核：计数器走**独立导出函数**，`EgohandVioWorldFrameInfo` 尺寸保持 **144**（4 个新 DLL 与旧库一致）。

## 3. 结论（区分"能证明"与"不能证明"）

### 3.1 可以确认：门限确实在拦截，且显著减少远点供给

- **开关生效**：OFF 组 5 次全部 `depth_gate_rejected=0`，ON 组 5 次 710–1428（中位 830）。这与开关状态完全对应，排除"没生效"。
- **远点数量下降约 10 倍**：`>50 m` 的点数中位 **965 → 98**。
- 但**区间有重叠**（ON 最大 932 vs OFF 最小 89，`max(ON) > min(OFF)`），所以只能说"中位显著下降、分布整体左移"，**不能说每次必然更少**。

### 3.2 不能确认：极端尾部没有改善

- 深度 p95 中位只从 2345.7 → 2011.7，**区间大幅重叠**，ON 还有一次 6089.4（比任何 OFF 都差）。
- 说明：门限压住了**新建点的供给**，但**已存在的地图点仍会被 `FullInertialBA` 沿深度推远**，所以极端尾部不变。

### 3.3 因此对根因链的修正

原假设"远点不断产生 → 被 BA 推远 → 累积"只对了一半：
- **入口门限能减少"产生"**（已证明，≈10×）；
- **但"推远"这条路径独立存在**，且它才是造成公里级极值的直接原因。

→ 两个方向**都需要**，不能相互替代：
1. **入口**：绝对深度门限（本实验已验证有效，建议保留）；
2. **求解侧**：BA 内深度约束或解后 outlier 处理（仍未解决）。

## 4. 建议

1. **把 `System.thFarPoints` 或本门限之一固化进配置**（当前都默认关闭）。优先级：本门限（有计数器、有 5×2 数据）优于 `System.thFarPoints`（已证只拦新建点且无计数）。
2. **继续攻"推远"**：需要的是求解侧约束。注意此前"BA 后止血"两次失败，其中一次是动作设计错误（保留旧位置），已改为 `SetBadFlag` 但**尚未做 5×2 对照**——现在有了计数器和多轮流程，可以用同样方法补测。
3. 门限倍率可扫描：当前 100×基线 ≈ 6.5 m；可试 50×/200× 看远点数量与跟踪有效率的权衡。
