# 实验前置检查清单（P0：防止用旧产物做实验）

> 本文来自 2026-11-11 的连续教训：有 3 次对照实验因为"改的代码不在被加载的 DLL 里"或
> "无法确认机制是否生效"而完全无效，浪费了约 2 小时机时。

## 背景：真实发生的失败

| 实验 | 失败原因 | 代价 |
| --- | --- | --- |
| `System.thFarPoints`（配置） | 配置生效但只拦新建点 | 1 轮对照 |
| BA 后止血 首次 | 动作设计错（保留旧位置）+ 无计数 | 1 轮对照 |
| 绝对深度门限 首次 | 无计数，无法确认生效 | 1 轮对照 |
| **BA 后止血 5×2** | **加载的 DLL 是 20:19 构建，而 `SetBadFlag` 与计数器导出是之后才写的** | **10 次回放（约 25 分钟）** |

最后一次最典型：所有 10 次运行的 `point_clamp_rejected` 都是 0，看起来像"止血没效果"，
实际是"止血代码根本不在那个 DLL 里"。`egohand_vio_point_clamp.dll` 时间戳 20:19，
而改动在 20:1x–20:28 之间完成，重建后才包含。

## 强制检查清单（每次对照实验前必须全部通过）

### A. 产物与源码一致

1. `.dll` 的 `LastWriteTime` **晚于**所有相关源文件的 `LastWriteTime`：
   - `third_party/ORB_SLAM3/src/Optimizer.cc`
   - `third_party/ORB_SLAM3/src/LocalMapping.cc`
   - `third_party/ORB_SLAM3/src/ImuTypes.cc`
   - `third_party/ORB_SLAM3/include/Vio*.h`
   - `src/egohand/vio/native/vio_bridge.{h,cpp}`
2. `.build.json` 的 `source_tree_sha256` 与当前源码树一致（重建后会自动更新）。
3. 一键检查（建议每次实验前跑）：

```powershell
$dll = "src/egohand/vio/native/bin/egohand_vio_point_clamp.dll"
$newest = Get-ChildItem "third_party/ORB_SLAM3/src/Optimizer.cc","third_party/ORB_SLAM3/src/LocalMapping.cc",
    "third_party/ORB_SLAM3/src/ImuTypes.cc","src/egohand/vio/native/vio_bridge.cpp" |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
"dll  : " + (Get-Item $dll).LastWriteTime
"src  : " + $newest.LastWriteTime + "  (" + $newest.Name + ")"
if ((Get-Item $dll).LastWriteTime -lt $newest.LastWriteTime) { "!! DLL 过期，必须重建" }
```

### B. 能力符号存在

```powershell
$conda = $env:EGOHAND_VIO_PYTHON
& $conda -c @"
import ctypes, os
os.environ['PATH'] = os.environ.get('EGOHAND_VIO_LIBRARY_PATH', '') + os.pathsep + os.environ['PATH']
lib = ctypes.CDLL(os.environ['EGOHAND_VIO_LIBRARY'])
for s in ('egohand_vio_point_clamp_count','egohand_vio_depth_gate_rejected','egohand_vio_get_world_frame_info'):
    print(s, 'ok' if hasattr(lib, s) else 'MISSING')
"@
```

### C. 机制在运行期真的触发（最关键）

**开关打开后，计数器必须增长。** 先跑 200–300 帧小样，确认：

```powershell
$env:EGOHAND_VIO_POINT_CLAMP="1"   # 或 EGOHAND_VIO_DEPTH_GATE
.\.venv\Scripts\python.exe scripts\run_vio_stability_experiment.py --recording <rec> `
    --output results/vio/_smoke --library <dll> --frames 300
# 然后检查 poses.jsonl 末帧的 optimization_counters
```

判据：
- 计数器 **> 0** → 机制触发，可以进入正式对照；
- 计数器 **= 0** → **不要跑正式对照**，先查：开关是否传到子进程、条件分支是否被满足、
  拟合是否 `valid`、代码是否在 DLL 里（回到 A）。

### D. 对照设计

1. 同 DLL、同录制、同帧数、同 timing，只切一个环境变量；
2. 每组 **≥5 次**；
3. 主指标必须是**计数或分布**，不是单点位姿指标；
4. 报中位数 + 范围，并明确写出**区间是否重叠**（重叠时不能宣称优劣）。

## 一句话

**"开关打开后计数器还是 0" 的第一反应必须是"代码在不在这个 DLL 里"，
而不是"这个方案没效果"。**
