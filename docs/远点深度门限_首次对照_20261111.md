# 远点绝对深度门限：实现与首次对照（无效实验，不能定论）

配套：`docs/地图点深度发散_根因链_20261111.md`（根因链）、`docs/地图点止血_首次对照_20261111.md`（止血）

---

## 1. 实现了什么

在 `LocalMapping::CreateNewMapPoints` 的三角化判据之后，加了一个 **opt-in 的绝对深度门限**：

```cpp
if (DepthGateEnabled()) {
    const float baseline = std::max(mpCurrentKeyFrame->mb, 1e-6f);
    const float limit = DepthGateBaselineFactor() * baseline;   // 默认 100×b ≈ 6.5 m
    if (dist1 > limit || dist2 > limit) continue;
}
```

**为什么需要它**（已有实测依据）：
- 三角化判据 `cosParallaxRays < cos(2·atan2(mb/2, depth))` 的右端随 `depth` **趋近 1**，即**越远越宽松**；
- `mfMaxDistance = dist·levelScaleFactor` 是**相对自身距离**定义的，远点上界随之膨胀；
- `mbFarPoints/mThFarPoints` 虽已存在，但所有配置都没设 `System.thFarPoints` → 默认 0 → **过滤关闭**（已实测：开启 6.5 m 后仍被拉爆，因为它只拦新建点）。

新增文件：`third_party/ORB_SLAM3/include/VioDepthGate.h`
开关：`EGOHAND_VIO_DEPTH_GATE=1`（默认关闭）；倍率 `EGOHAND_VIO_DEPTH_GATE_BASELINE_FACTOR`（默认 100）
DLL：`egohand_vio_depth_gate.dll`（20:28）

## 3. 判读：**这次对照无效，不能下结论**

**表面上的"改善"**：event6 的深度中位数从 36.48 → **9.11 m**（地图整体尺度更接近桌面场景），说明门限确实压住了大多数点的深度。

**但**：
1. **点数差异大**：event6 OFF 1187 vs ON 938（-21%），event4 OFF 846 vs ON 965（+14%）——两次运行的建图路径不同，**不是配对对照**。
2. **极端远点反而更多**：event4 的 `>50 m` 从 22 → 32、event6 从 51 → **89**；`depth_max` 也没有下降（event4 584 vs 449）。
3. **门限在 `fullba_before` 阶段就没能挡住远点**：event6 ON 的 before 阶段 `>50 m` 已是 54（OFF 43），`depth_p95` 60.17（OFF 14.29）。

第 3 点尤其关键：说明**门限没有按预期工作**，或远点的产生路径不在 `CreateNewMapPoints` 这一处（例如来自 `UpdateLocalMap` 融合、三角化之外的来源、或旧点被 BA 推远后保留）。

→ **诚实结论：不能判定门限有效或无效。** 有效果迹象（event6 深度中位数下降到 9.11 m），但同时出现远点增多、深度上界未降、点数不可比三类反证。

## 4. 必须先查清的三件事（再谈效果）

1. **门限是否真的在生效**：需要在编译或运行期打印"被门限拒绝的点数"。当前没有任何计数器，无法确认它拦了多少、是否在正确的位置被调用。**这是和止血一样的可观测性缺失问题。**
2. **远点的真实来源**：`CreateNewMapPoints` 之外还有 `SearchInNeighbors` 融合、`UpdateLocalKeyFrames` 等会引入/保留点；如果远点主要来自旧点被 BA 推远后保留，那"入口门限"必然治不好。
3. **配对对照**：同一份 `EGOHAND_VIO_DEPTH_GATE` 开关，需要在**固定调度**下各跑 ≥5 次，比较远点数量的**分布**而不是单次值。

## 5. 建议

**在补上拒绝计数之前，不要继续做效果对照** —— 这已经是连续第三次（远点过滤 thFarPoints、止血、深度门限）因为"无法确认机制是否按预期生效"而得到无效结论。

正确顺序：
1. 给门限加拒绝计数（导出函数 + `poses.jsonl` 字段），确认它在生效；
2. 统计"每轮新建点中远点占比"，确认远点确实来自 `CreateNewMapPoints`；
3. 以上两条成立后，才做配对的多轮对照。
