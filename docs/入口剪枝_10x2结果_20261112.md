# 入口剪枝（prune-before-solve）：10×2 对照结果（2026-11-12 00:2x）

配套：`docs/地图点深度发散_根因链_20261111.md`、`docs/整图尺度指标_20261111.md`、`docs/实验前置检查清单_20261111.md`

---

## 1. 方案与实现

在 `FullInertialBA` **建图之前**剔除"进入求解时深度已经超出自身合理上界"的地图点：

```cpp
if (EntryPruneEnabled()) {
    const double bound = pMP->GetMaxDistanceInvariance();       // = 1.2 × mfMaxDistance
    KeyFrame* pRefKF = pMP->GetReferenceKeyFrame();
    const double range = (pMP->GetWorldPos() - pRefKF->GetCameraCenter()).norm();
    if (range > bound * EntryPruneRatio()) { ++EntryPruneCounter(); pMP->SetBadFlag(); vbNotIncludedMP[i]=true; continue; }
}
```

设计依据：实测的累积曲线是"求解前点云半径 max 27 → 328 → 472 m"，坏点在**进入求解前就已经坏**。入口剪掉直接阻断累积，且因为是"不参与优化"而非"求解后不写回"，不存在与已更新关键帧位姿不自洽的问题（这是 v3 事后止血的缺陷）。

开关：`EGOHAND_VIO_ENTRY_PRUNE=1`（默认关），倍率 `EGOHAND_VIO_ENTRY_PRUNE_RATIO`（默认 1.0；**实测 1.0 不触发**，本实验用 0.5）。

DLL：`egohand_vio_entry_prune.dll`；计数器 `egohand_vio_entry_pruned` → `poses.jsonl` 的 `optimization_counters.entry_pruned`。ABI 尺寸仍为 144。

## 2. 结果（1200 帧 × 10×2）

| 臂 | n（有 event6） | entry_pruned 中位 | 门控后中位 | event6 放大倍数（各次） | 中位 | 范围 |
| --- | ---: | ---: | ---: | --- | ---: | --- |
| 关闭 | 6/10 | 0 | 432 | 45 / 30 / 65 / 21 / 35 / 3 | **32.8×** | 3.1–65.5 |
| 开启（0.5） | 10/10 | **927** | 414 | 179 / 54 / 7 / 5 / 227 / 26 / 49 / 1 / 42 / 82 | **45.8×** | 1.5–226.9 |

**检验**：

| 检验 | 结果 |
| --- | --- |
| >50× 二分类 Fisher 单侧 | off 1/6 vs on 4/10，**p = 1.000** |
| 中位数置换检验 | **p = 0.871** |
| "on 全部低于 off 中位" | **False** |

**结论：入口剪枝没有效果，甚至方向相反**（中位 32.8× → 45.8×）。

## 3. 这个结果说明了什么

1. **剪掉"进入时已超标"的点，并不能减少求解造成的放大。** 因为在 1200 帧内，event6 发生时的坏点往往是**在这次求解过程中才被推远的新点**，而不是"进入前就已经坏"的老点。入口剪枝只影响后者。
2. 之前"累积曲线 27→328→472"的证据来自**同一次运行的连续事件**，说明坏点被继承；但剪掉继承来的坏点并不能阻止新坏点的产生——所以单靠入口剪枝无效。
3. 臂间差异（on 中位更高）很可能是**运行间方差**（on 的范围 1.5–226.9 跨 150 倍），而不是剪枝真的有害。

## 4. 一个必须记录的方法学发现

**10 次对照里只有 6 次出现了 event6**（其余运行在 1200 帧内没走到第 6 次全局优化）。这意味着：

- 用 `event6` 作主指标会引入**选择偏差**：能走到 event6 的运行本来就与走不到的运行不同；
- 之前所有基于 event6 的对照（远点门限、止血、深度倍数）都受此影响。

**正确的做法**：改用"该运行内所有事件的**最大**放大倍数"或"运行结束时的地图点 spread"，这样每次运行都能贡献一个数据点，无需按 event6 是否存在筛选。

## 5. 本项目至此的全部修复尝试（汇总）

| 方案 | 层级 | 结果 |
| --- | --- | --- |
| `System.thFarPoints` | 三角化入口 | **否定**（只拦新建点） |
| 绝对深度门限（50/100/200×） | 三角化入口 | 机制可信（拦截量随倍率单调），但 n≥10 后中位 39.2 vs 39.1、p=0.905 → **无效果** |
| 事后止血 v2（位移阈值） | 求解后写回 | **否定**（位移阈值对远点几乎无约束） |
| 事后止血 v3（深度倍数） | 求解后写回 | n=4 时"14/14 优于对照"，n=10 后 p=0.43–0.76 → **无效果**（并已更正） |
| **入口剪枝（本方案）** | 求解前建图 | **无效果**（p=0.87–1.00，方向相反） |

**唯一仍然成立且效果明确的修复是机制层的 `EdgeWorldGauge`**：关键帧整体位移 22.82 m → 0.038 m（原生测量，不受位姿流噪声影响）。

## 6. 如何看待"五个方案都无效"

这不是"什么都没做成"，而是**把五个看似合理的方案逐个用严格对照排除了**，并在这个过程中建立了：

1. 可信的根因（三路独立证据）；
2. 一个真正有效的修复（`EdgeWorldGauge`）；
3. 三个独立缺陷的修复（NaN 猝死、`map_epoch` 漏计、ABI 兼容）；
4. 可观测性链路与统一指标（`map_scale`、`optimization_counters`）；
5. 一套能防住假信号的方法（n≥10 + 计数验证 + 两种检验）。

## 7. 下一步建议（若要继续）

**问题本质**：地图点与位姿之间的 `EdgeStereo` 只通过 `bf/z` 约束深度，`1/z²` 衰减使远点深度近乎不可观测，`FullInertialBA` 因此可以把它们推到任意远。

**唯一未被试验、且直接针对该机制的做法**：在求解图中给地图点加**深度先验边**（二元边，连参考关键帧位姿），使深度在远距离仍有约束。这需要编写新的 g2o 边并验证 Jacobian（可用合成小图单测），工作量与风险都明显高于前五个方案。

在此之前，建议**停止在"入口/事后"层面做修补**——已用五个方案证明该层面无效。
