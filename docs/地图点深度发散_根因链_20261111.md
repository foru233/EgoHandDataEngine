# 地图点深度发散：代码级根因链（2026-11-11）

配套：`docs/VIO_跳变根因取证总报告_20261111.md`（总报告）、`docs/VIO_实验C_结论修正_20261111.md`（实验 C 与阶段追踪）
数据：`results/vio/gauge_diag_on_20261111/native_diagnostics`（`--diagnostics`，1200 帧，`egohand_vio_stability_gauge_constraint.dll`）

---

## 1. 现象与关键定量

`FullInertialBA` 求解后部分地图点位移到公里级。逐项排除后的结果：

| 检查项 | 结果 |
| --- | --- |
| 位移与**边条数**的关系 | 无（稳定点与发散点 edge 中位都是 2） |
| 位移与 **`observations`** 的关系 | 无（发散点中位 4，与稳定点同） |
| 位移与 **stereo/mono 边比例** | 无（两组的 stereo 边占比都约 96–98%） |
| **位移方向** | **与"点位置矢量"的 \|cos\| 中位 0.828、p95 1.000；大位移（>100 m）组中位 1.000** |
| **求解前深度** | 见下表 |

| 事件 | 分组 | n | **求解前深度** 中位 / p95 / max |
| --- | --- | ---: | --- |
| event4 | 稳定 <1 m | 786 | **2.07** / 6.22 / 24.71 m |
| event4 | 中 1–100 m | 42 | 6.37 / 20.06 / 73.23 m |
| event4 | **发散 >100 m** | 38 | **118.41 / 304.37 / 326.11 m** |
| event6 | 稳定 <1 m | 686 | **1.96** / 5.39 / 9.57 m |
| event6 | 中 1–100 m | 55 | 5.04 / 78.55 / 123.28 m |
| event6 | **发散 >100 m** | 75 | **73.28 / 307.72 / 470.29 m** |

**两个决定性事实**：

1. **发散是纯深度方向的**：位移方向与视线方向夹角 \|cos\| 中位 **1.000** → 横向几乎不动，只沿深度飞出。这是"深度不可观测"的典型形态（重投影误差对深度不敏感，尤其点与相机间几乎无平移时）。
2. **这些点在优化前就已经是远点**：发散组的求解前深度中位 73–118 m，而稳定组只有 2 m。桌面场景（标定/三角化目标距离 0.5–1.5 m）里出现 300–470 m 的点，本身就不合理。

→ 客观描述应修正为：**全局 BA 沿深度方向"放大"了三角化阶段就已产生的远点**，而不是"BA 凭空造出畸变"。此前"由每次求解自身产生"的说法需要收窄成"由求解放大并跨事件累积"。

## 2. 代码级机制

### 2.1 三角化门限在"远点"上最宽松（`LocalMapping::CreateNewMapPoints`）

```cpp
if(bStereo1) cosParallaxStereo1 = cos(2*atan2(mpCurrentKeyFrame->mb/2, mpCurrentKeyFrame->mvDepth[idx1]));
else if(bStereo2) cosParallaxStereo2 = cos(2*atan2(pKF2->mb/2, pKF2->mvDepth[idx2]));
cosParallaxStereo = min(cosParallaxStereo1, cosParallaxStereo2);
if(cosParallaxRays<cosParallaxStereo && cosParallaxRays>0 && (bStereo1 || bStereo2 ||
   (cosParallaxRays<0.9996 && mbInertial) || (cosParallaxRays<0.9998 && !mbInertial)))
```

`cos(2*atan2(mb/2, depth))` 随 `depth` 增大而**趋近 1**。也就是说：**该特征点的双目深度越远，判据 `cosParallaxRays < cosParallaxStereo` 越容易满足**。远点的三角化门限因此最宽松 —— 远点更容易被接受，而它们的深度恰恰最难被约束。

（本仓库 `mb` = 双目基线，半分辨率配置下 `Stereo.b = 0.06527 m`）

### 2.2 距离上下界是"相对于自身观测距离"的（`MapPoint::UpdateNormalAndDepth`）

```cpp
mfMaxDistance = dist*levelScaleFactor;
mfMinDistance = mfMaxDistance/pFrame->mvScaleFactors[nLevels-1];
```

`dist` 是该点在其参考关键帧里的深度。**远点的 `mfMaxDistance` 也按同一比例放大**，所以"深度是否超界"这类基于 `mfMaxDistance` 的检查（`MapPoint::isBad()` 只返回 `mbBad` 标志，本身不做距离判断；距离检查散落在 `Tracking`/`LocalMapping` 里）对远点同样宽松。

### 2.3 全局 BA 沿深度方向把它们推得更远

深度方向信息矩阵接近奇异 → 求解器可沿该方向自由移动而不显著增加代价（`EdgeStereo` chi2 中位 1.446 → 1.307 甚至下降），于是远点被继续推远（>100 m）。下一轮优化以更差的初值开始 → **跨事件累积**：

| 事件 | 求解前点云半径 max | 求解后 |
| --- | ---: | ---: |
| event1→2 | 27 m | 98 m |
| event3→4 | 328 m | 644 m |
| event5→6 | 472 m | 4052 m |

## 3. 与"整图重锚"的关系（两个独立问题）

| 问题 | 机制 | 状态 |
| --- | --- | --- |
| (a) 整图重锚 | `FullInertialBA` 缺世界平移 + 重力轴 yaw 约束，整图沿零空间漂移 | **已被 `EdgeWorldGauge` 修好**（KF 位移 22.82 m → 0.038 m） |
| (b) 深度发散 | 远点的深度方向信息奇异，被 BA 沿视线推远并跨事件累积 | **未修**，且与 (a) 无关 |

因此"加规范约束"不能解决 (b) —— 实测 ON 臂 event6 点云 p95 2554 m，比 OFF 的 1678 m 更差（不同运行的建图过程不同，不能直接比大小，但至少说明约束对 (b) 无效）。

## 4. 已做的对照实验：只掐源头（远点过滤）**不够**

### 4.1 发现：远点过滤默认是关闭的

`System.cc` 里：

```cpp
if(settings_) mpLocalMapper->mThFarPoints = settings_->thFarPoints();
else          mpLocalMapper->mThFarPoints = fsSettings["thFarPoints"];
if(mpLocalMapper->mThFarPoints!=0) { cout << "Discard points further than ..."; mpLocalMapper->mbFarPoints = true; }
else                               mpLocalMapper->mbFarPoints = false;
```

`Settings::readOtherParameters` 读的是 **`System.thFarPoints`**，缺省值为 0 → **`mbFarPoints = false`，远点过滤完全关闭**。当前所有 ORB 配置（`configs/vio/*.yaml`）都没有这个键，所以一直是关的。

对照实验用的配置：`configs/vio/vs030_rectified_half_farpoints.yaml`（在 `vs030_rectified_half_calibration2.yaml` 基础上加 `System.thFarPoints: 6.5`，6.5 m ≈ 100×基线）。日志第 54 行确认生效：`Discard points further than 6.5 m from current camera`。

### 4.2 结果：仍被拉爆

| 事件 | 阶段 | 过滤关闭（OFF） | **过滤开启 6.5 m（ON）** |
| --- | --- | --- | --- |
| event2 | solved max | 97.6 m | 110.0 m |
| event4 | solved max | 642.6 m | **410.7 m** |
| event6 | solved p95 / max | 2552.9 / 4050.7 m | **1726.3 / 4340.6 m** |
| event6 | solved 深度 p50 | 2.42 m | **95.50 m** |

（两次运行的地图演化不同：ON 组 1047 点 vs OFF 816 点，因此不是严格配对对照，只能看量级。）

**结论：只掐源头不够。** `mbFarPoints` 只在 `CreateNewMapPoints` 里过滤**新建点**：
- 不影响已经存在的远点；
- 不阻止后续 `FullInertialBA` 把已有远点沿深度继续推远；
- 因此 event6 的 max 反而更大（4340.6 m），深度中位数也被整体抬高（2.42 → 95.50 m）。

### 4.3 因此修复必须落在"求解后"

1. **全局 BA 后 outlier 止血**：地图点位移超阈（相对 >5% 或绝对 >1 m）即标记 bad / 不写回地图，阻断跨事件累积 —— 这是本次实验指向的最小有效动作。
2. **在求解图里加深度先验**（如 `EdgePointDepthPrior`），从源头约束深度方向 —— 改动更大，需单独对照。
3. 远点过滤（`System.thFarPoints`）可以作为**配套**保留（它减少远点供给），但**不能单独作为修复**。

## 5. 可选的修复方向（更新后的优先级）

| 优先级 | 动作 | 预期 | 风险 |
| --- | --- | --- | --- |
| 1 | 全局 BA 后位移 outlier 止血 | 阻断 27→328→472 m 的累积 | 低（只影响地图写入） |
| 2 | 求解图中加深度先验 | 从机制上约束深度方向 | 中高（改求解图） |
| 3 | 开启 `System.thFarPoints`（6.5 m） | 减少远点供给，**已实测不足以单独修复** | 低（配置项） |
| 4 | 给 `mfMaxDistance` 加绝对上限 | 防止上界随自身距离放大 | 低 |

## 6. 尚未证明 / 局限

- 上述是**相关性 + 代码路径 + 一次对照实验**的推论；远点过滤的对照不是严格配对的（两次运行建图不同），需要固定调度后重复。
- `cosParallaxStereo` 依赖 `mvDepth`，若 `mvDepth` 本身有误（例如错误视差），门限也会被带偏；未单独验证 `mvDepth` 的准确性。
- 未统计"远点"在各阶段的数量占比随时间的演化（只有半径分位）。
- **条件数实测结果不支持"信息矩阵普遍奇异"**：`event6` 求解前 883 个点中，`condition_number` 的 p50 仅 **67**、p90 **280**，只有 **9 个点（1%）** 真正接近奇异（`sigma_min` 1.6e-04）；而实际发散的点有 75 个（9%）。因此"深度方向信息奇异"只能解释一小部分发散，不能作为主因 —— 详见 `docs/地图点条件数_初步结果_20261111.md`。该项分析还缺 solved 阶段数据（该次回放在 984 帧因 `0xC0000409` 崩溃），尚不能最终定论。
