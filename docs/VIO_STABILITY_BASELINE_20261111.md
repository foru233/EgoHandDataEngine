### 2. 跳变模式分析

**所有 >0.5m 的跳变均发生在：**
1. **BA2 transition** (inertial_scale_finalized: False → True) 
2. **Epoch 边界** (map_epoch 变化)
3. **时间间隔 >1s** (有效位姿之间存在 NOT_INITIALIZED 或 LOST 状态)

**同 epoch 内正常运动统计：**
- 位置步长中位数: 0.0075 - 0.0293m
- P95 步长: 0.0193 - 0.0793m  
- 最大步长: 0.0459 - 0.1099m
- 这些数值符合 30fps 相机的正常运动

**结论：逐帧跟踪本身是稳定的，问题在全局优化时刻。**

### 4. 代码因果分析

根据 `docs/VIO_JUMP_AUDIT_20261111.md` 和源码：

```
LocalMapping.cc:223  → InitializeIMU(0,0,true) 启动 VIBA2
LocalMapping.cc:1337 → FullInertialBA(bFixLocal=false, bInit=false)
Optimizer.cc:423     → 位姿顶点创建，未固定原点
                       视觉+IMU 约束不能观测整体平移自由度
LocalMapping.cc:1392 → 优化结果写回关键帧和地图点
                    → map epoch 增加
Python 侧           → 检测 epoch 变化，清空轨迹，重新适配视图
```

**强嫌疑根因：**
`FullInertialBA` 在 `bFixLocal=false` 时，没有固定世界坐标原点，导致优化过程中整体平移自由度无约束。g2o 求解器可能将整图平移到数值上更"舒适"的位置，导致优化前后坐标系发生大幅漂移。

### 5. 当前无法确认的

1. **280m 是否为纯刚体平移？**
   - 需要优化前后同 ID 关键帧/地图点快照
   - 拟合 SE(3)/Sim(3) 变换并计算残差
   - 检查关键帧间相对距离是否保持

2. **是否存在非刚体畸变？**
   - 需要检查重投影误差变化
   - IMU 残差变化
   - 地图点分布形变

3. **优化是否收敛？**
   - 需要 g2o 优化日志：迭代次数、chi-square、梯度范数
   - 是否存在异常边或非有限值

4. **固定原点是否足够？**
   - 需要考虑航向自由度
   - 重力方向约束
   - 惯性偏置和速度自由度
   - 避免过约束妨碍重力优化

## 已确认事实
1. ✅ 跳变确实存在，最大达 280m
2. 本结论不能推广为“所有大跳变都在 BA2/epoch 转换”。`1794365666918157500` 日志的连续记录同 epoch、dt≤0.2s 样本有124次大于0.5m，最大8.414m；本次新录制的v9完整回放也有9次，最大24.612m。
3. 某些窗口 P95<0.08m 不排除少量严重异常，不能据此认定同 epoch 内跟踪稳定。需同时报告最大值、异常次数和有效率。可复核产物见 `results/vio/stability_baseline/experiment_comparison.json` 与逐组 `analysis/report.json`。
4. ✅ 代码中存在全局平移自由度未约束的机制
5. ✅ 用户体感"跳变后更稳"与短期步长减小一致
