## 1. 这次实验为什么终于是有效的

前两次失败的根因已定位并修复：

| 失败 | 根因 | 修复 |
| --- | --- | --- |
| 首次对照 | 动作是"保留旧位置" → 地图与关键帧位姿不自洽 | 改为 `SetBadFlag()` |
| **5×2 第一次（10 次回放全为 0）** | **① DLL 是 20:19 构建，改动在之后；② 止血只写在 `nLoopId==0` 分支，而初始化路径 `nLoopId = mnCurrentKeyFrame->mnId ≠ 0` 走 `mPosGBA` 分支，永远不执行** | 重建 + 把检查提到 `nLoopId` 分叉之前 |

有效性前置条件（全部通过）：

- DLL（21:5x）晚于所有源文件；符号 `egohand_vio_point_clamp_count` 存在；ABI 尺寸 144 未变
- 开关打开时计数增长（300 帧小样 = **59**），关闭时为 0
- `SetBadFlag()` 上下文安全：`Map::EraseMapPoint` 只做 `erase` 不 delete，`vpMPs` 副本指针仍有效，循环后不再访问，无锁序问题

## 2. 结果（1200 帧 × 5×2）

### 2.1 机制确认生效

| 臂 | 止血丢弃计数 |
| --- | --- |
| OFF（5 次） | **0, 0, 0, 0, 0** |
| ON（5 次） | 438 / 567 / 301 / 1138 / 1811，中位 **567** |

### 2.2 安全指标（止血没有把地图砍稀、没有破坏重锚检测）

| 指标 | OFF 中位 | ON 中位 | 判断 |
| --- | ---: | ---: | --- |
| 原生有效位姿 | 1078 | 1056 | 基本持平（-2%） |
| **门控后有效位姿** | 417 | **442** | **未下降**（+6%）✔ |
| `world_frame_revision` | 1 | 1–3 | 仍能正常检出 ✔ |

### 2.3 主指标：**不能宣称有效**

| 指标 | OFF | ON |
| --- | --- | --- |
| event6 `>50 m` 点数 | 中位 **93**（85–1021） | 中位 **855**（83–1069） |
| event6 深度 p95 | 中位 2739.8 | 中位 672.5 |

看起来 p95 从 2739.8 → 672.5（好），但：

1. **`>50 m` 点数中位反而从 93 升到 855**（差 9 倍，方向与预期相反）；
2. **区间完全重叠**：OFF 85–1021，ON 83–1069（`min(ON) > min(OFF)` 且 `max(ON) > max(OFF)`）；
3. **ON 组有 2/5 次根本没出现 event6**（OFF 只有 1/5），事件出现率不一致，样本不可配对比较；
4. ON 组 p95 有一个 **9441.5** 的极端值（比所有 OFF 都差）。

→ **结论：止血在机制上生效、在安全性上可接受，但在这组数据上无法证明它减少远点。**

## 3. 为什么可能"越治越糟"

标 bad 会触发 `EraseMapPointMatch`，从关键帧里删除这些匹配。对**远点**而言，它们往往承担"跟踪冗余"的角色；一次删掉 300–1800 个点（含部分仍在使用的点），可能导致：

- 可用地图点骤减 → 关键帧之间可匹配点变少 → 局部 BA 的约束变弱；
- 关键帧因缺少匹配被判定为冗余或 bad，引发新一轮重建；
- `event6` 这类全局优化在新的、更稀疏的图上运行，反而更容易把残余点推远。

**这是"止血"这类事后删除方案的固有风险**：它只删除症状，不改变求解行为。

## 4. 结论与建议

| 项 | 结论 |
| --- | --- |
| 机制 | 已实现、已确认触发、安全可接受 |
| 效果 | **未证明**（主指标方向相反、区间重叠、事件出现率不一致） |
| 建议 | **不建议启用**；若要继续，需先解决"删点导致跟踪冗余下降"的问题（例如只对"几乎无观测"的点标 bad，或用更小的阈值窗口） |

**更值得投入的方向**仍然是入口侧：绝对深度门限已有 5×2 证据（远点（>50 m）中位 965 → 98，约 10×），虽然极端尾部未改善，但方向一致、机制明确、不改变求解行为、风险低。

## 6. 限制

- 两组 event6 出现率不同（4/5 vs 3/5），无法做配对比较；这是 ORB 建图路径差异造成的，非实验设计问题。
- 单次 1200 帧，未覆盖长时运行。
- 未做阈值扫描（当前 `max(1.0 m, 5%·|p|)`）；更严或更松的阈值可能改变结论。
- 未统计"被删点中仍被多少关键帧观测"，无法定量验证"删除导致冗余下降"这一解释。
