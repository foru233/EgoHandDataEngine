# 世界系变更检测（world_frame_change）：规则、局限与接入（2026-11-11）

配套实现：`src/egohand/vio/world_frame.py`（纯函数）、`scripts/audit_world_frame_changes.py`（CLI）、
`tests/test_vio_world_frame.py`。背景取证见 `docs/VIO_27m跳变取证_20261111.md`。

## 1. 要解决的问题

`map_epoch = map_id<<40 | reset_revision<<20 | big_change_revision` 只标记**地图身份**。
`FullInertialBA(bFixLocal=false)` 缺少世界平移与重力轴 yaw 约束时，一次求解可以把整张图刚体
搬移（event6：75 个关键帧整体平移 22.82 m、旋转 0.40°、`se3.scale=1.0`）而**不改动 epoch 编码**。
于是位姿流上出现"相邻两帧 27.3 m、之后 1.7 cm/帧 正常跟踪"的段，而
`map_epoch`/`map_change_index` 看起来都"没问题"。

因此需要一条独立判据：**在同一次世界系定义内，位姿不应出现物理上不可能的相邻帧位移**。

## 2. 判定规则

对**相邻两个原生有效位姿**（`raw_pose_valid`/`pose_valid` 为真、`raw_matrix` 为 4×4 全有限；
门控后 `matrix` 为 null 不影响判断），计算 `dt`、平移 `‖t₁−t₀‖`、相对旋转角
`acos((tr(R₀ᵀR₁)−1)/2)`，然后按 epoch 三要素分类：

| 条件 | `kind` | 含义 |
| --- | --- | --- |
| 位移 ≤ `jump_m`，或 `dt` 不属于 `(0, max_gap_s]` | `normal`（不产生事件） | 普通相邻帧；长间隔不判定（缺测不等于跳变） |
| 位移 > `jump_m`，且 `map_id`/`reset_revision`/`big_change_revision` **全不变** | `world_frame_change` | **同一世界系内的整图重锚**：记为世界系变更，不当成真实运动或帧间抖动 |
| 位移 > `jump_m`，且 epoch 三要素**有变化** | `map_switch` | 地图/代切换，本身不属于同一世界系轨迹 |
| 位移 > `jump_m`，但 `map_epoch` 缺失/不可解码 | `epoch_unknown` | 无法断言同一世界系，只作待查候选（旧日志） |

默认阈值 `jump_m=1.0 m`、`max_gap_s=0.2 s`（约 30 Hz 下的 6 帧窗口）。
阈值只用于**筛选候选**：不做插值、不改写矩阵、不参与质量门控，`normal` 不进入事件列表。

复用而非重写：epoch 解码与原生位姿校验直接复用 `scripts/audit_vio_stability.py` 的
`map_identity()` 与 `raw_matrix()`（按文件路径导入；脚本不可用时按同一语义兜底，代码内已注明来源）。
行号口径与该脚本一致：按 `poses.jsonl` 记录序号、1 起，畸形行保留空占位。

## 3. 本次录制上的结果（`results/vio/world_frame_audit_20261111/`）

  `epoch 9 → 9`（`map_id 0 / reset 0 / big_change 9` 全不变），`record_adjacent=True`。
  与已知的 27.3 m 跳变（第 1080 行）**完全吻合**，`native_jump_detected=True`、
  `quality_status="位姿突变已拒绝：平移 27.307 m，旋转 7.0°"` 可交叉印证。
- `jump_m=0.5 m`（`jump_m_0.5/`）：4 处事件，与 `docs/VIO_27m跳变取证_20261111.md` 的

  搬移反复出现，说明这个机制不是一次性故障，只是幅度远小于 pair2 的 27 m。

## 4. 已知局限

1. **仅凭位姿流无法区分"纯刚体重锚"与"重锚 + 地图点畸变"**。同 epoch 内的大位移只能证明
   世界系被整体搬走；是否同时把地图点拉到公里级（event6 的 p95 1650 m）需要原生快照
   （`VIO_FRAME_SNAPSHOT_NOTE_20261111.md`）对同 ID 关键帧/地图点做 SE(3) 拟合。
   本模块因此只输出"位移 + 旋转 + epoch 是否变化"，不给"重锚是刚性的"结论。
2. **阈值选择直接改变计数**：本录制上 `jump_m=1.0` 得 1 处、`0.5` 得 4 处（含 1 处 `map_switch`），
   更小阈值会开始收进正常快速运动与单帧跟踪退化；`max_gap_s` 越小越保守，
   但会漏掉帧率抖动造成的相邻记录间隔。两个阈值都随报告落盘（`thresholds`），换阈值必须重跑。
3. **距离以外的东西看不见**：旋转很小而位移很大是这个机制的典型特征，但"旋转大、位移小"的
   重锚（阈值内）不会被捕获；Atlas 侧的真实地图切换与 `big_change` 递增同样表现为
   `map_switch`，两者在本判据里不可区分。
4. **不是误差度量**：`translation_m` 只说明相邻原生位姿的差，不说明哪一帧"错"；
   门控拒绝、`display_segment` 与显示连续性另有口径，本模块不改它们。
5. **时间戳单调性未强制**：`dt ≤ 0` 的相邻对被归为 `normal`（不判定），非单调性请用
   `audit_vio_stability` 的 `non_monotonic_frame_intervals` 观察。

## 5. 接入方式（只读，不改现有配置与代码）

- **审计**：`scripts/audit_vio_stability.py` 的 `jump_cases` 只回答"是否超阈值"；把本模块输出当作
  它的**注解**：同一 `(previous_line, current_line)` 在 `world_frame_changes.json` 里是
  `world_frame_change` ⇒ 该跳变应计入"世界系重锚"，而不是"同段异常步长/跟踪误差"；
  是 `map_switch` ⇒ 归入跨段。两者行号同口径，可直接按行对 join。
- **GUI**：在拿到位姿结果的同一处调用 `classify_step((prev_line, prev_row, prev_matrix),
  (line, row, matrix))`；当 `kind == "world_frame_change"` 时把该帧标记为
  "世界系已重锚（位移 X m，epoch 未变）"，据此决定是否断开显示轨迹/重置视角 ——
  这比"epoch 变了才断"更符合实际（27.3 m 那次 epoch 没有变）。`PoseContinuityCorrector`
  处理的是显示连续性，本模块只做标识，二者可叠加使用。
- **验收/汇总**：报告里把 `world_frame_change_count` 与 `map_switch_count` 分开统计，
  避免重锚被算作跟丢或精度问题；跨运行比较时固定同一组 `jump_m`/`max_gap_s`。
- **CLI**：`python scripts/audit_world_frame_changes.py --poses <poses.jsonl> [--output <dir>]
  [--jump-m 1.0] [--max-gap-s 0.2]`，打印事件表并写 `world_frame_changes.json`。
