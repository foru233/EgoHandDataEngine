# 远点门限倍率扫描：50× / 100× / 200×（2026-11-11）

配套：`docs/远点深度门限_5x2对照结果_20261111.md`（100× 的 5×2 结论）

---

## 1. 三档倍率的拦截量（基线 0.0653 m）

| 倍率 | 对应绝对距离 | 拒绝点数（各次） | 门控后有效位姿 |
| --- | --- | --- | --- |
| 关闭 | — | 0, 0, 0, 0, 0 | 中位 406 |
| **50×** | ≈ **3.27 m** | 3990 / 4434 | 452 / 364 |
| **100×** | ≈ **6.53 m** | 710 / 751 / 830 / 904 / 1428（中位 830） | 中位 461 |
| **200×** | ≈ **13.1 m** | 109 / 109 | 395 / 453 |

拦截量随倍率单调变化，符合预期：**50× 拦得最狠（≈4000 点，约 100× 的 5 倍）、200× 最松（109 点，仅 100× 的 1/8）**。

## 2. 对远点（event6 `>50 m` 点数）的影响

| 倍率 | event6 `>50 m` 各次 | event6 深度 p95 |
| --- | --- | --- |
| 关闭（5 次） | 85, 1021, 99, 87, 无 | 中位 2739.8 |
| 100×（5 次） | 285, 98, 932, 75, 57（中位 98） | 中位 2011.7 |
| 50×（2 次） | 1008, 888 | 1072.3 / 1366.4 |
| 200×（2 次） | 983, 70 | 27640.7 / 3684.2 |

**注意**：`>50 m` 点数在这些运行里经常等于 event6 的总点数（例如 50× 的 1008/1008、888/888），说明**在某些运行里几乎全部点都超过 50 m** —— 这是全局优化把整图尺度推大造成的，不是"剩余少量远点"。

因此 `>50 m` 的**绝对计数在这个指标上不稳定**，跨倍率比较只能看趋势，不能当精确度量。

## 3. 能不能从扫描得出"最佳倍率"

**不能。** 理由：

1. **样本量不足**：50× 与 200× 各只有 2 次，而同一配置的运行间方差极大（关闭组 `>50 m` 可从 85 变到 1021）。
2. **指标不稳定**：如上所述，`>50 m` 计数常等于总点数，无法区分"少量远点"与"整图被放大"。
3. **100× 的 5×2 结论本身就只是"中位下降、区间重叠"**，谈不上确定最优。

## 4. 能确定的事

1. **门限确实按倍率拦截**：拒绝数单调随倍率变化（50× ≈ 4000、100× ≈ 830、200× ≈ 109），机制可信。
2. **门控后有效位姿没有系统性下降**：三档都在 364–461 之间，与关闭组（406）同量级 → **门限没有明显损害跟踪**。
3. **50× 拦截量过大**（≈4000 点，占新建点很大比例），有"过度过滤"风险；**200× 拦截量偏小**（109），对远点供给的压制有限。
4. 100×（6.5 m）在"拦截量与跟踪保持"之间是当前较合理的折中，但**这只是工程判断，不是统计结论**。

## 5. 建议

1. **若要固化配置，先用 100×**（唯一有 5×2 数据的档位），并保留环境变量可覆盖。
2. **不要用 `>50 m` 点数作为唯一验收指标**：应先加一个"整图尺度"指标（例如关键帧位姿的平均深度），把"远点多"与"整图被放大"分开。
3. 若继续扫描，至少每组 5 次，并改用更稳的指标（建议：`event6` 求解前后**地图点深度的中位数**，以及 `world_frame_revision` 计数）。
