# VS030 标定结果 2 接入

原始文件 `标定结果/2/data3-camchain-imucam(1).yaml` 保持不变。执行
`.venv\Scripts\python.exe scripts/prepare_vs030_calibration2.py` 可由它和
`configs/vio/vs030_rectified_half.yaml` 重新生成候选标定及半分辨率 ORB 配置。

默认采集、实时 VIO 和新录制使用 `标定结果/2/data3-camchain-imucam-measured.yaml`；
实时 ORB 配置由 `configs/vio/live_timing.yaml` 选择
`configs/vio/vs030_rectified_half_calibration2.yaml`。切换后须重启程序并重新开始采集。
历史录制的原始标定快照应保留，不应替换成新标定。注意：目前 GUI 的离线 VIO 回放
实现尚未自动采用录制目录中的标定与 ORB 配置，可能混用当前标定和默认 ORB 配置，
因此不可仅凭快照文件存在就认为历史回放采用了它们；做定量对照须显式统一配置。

用户提供的位置解释为**相机光心在 IMU 坐标系下的位置**，单位毫米。按照结果 2 的
cam0–cam1 双目外参和 cam0–IMU 旋转换算，cam1 相对 cam0 在 IMU 坐标轴中的位置约为
`(-65.233, +2.124, -0.285) mm`。因此采用 cam0 `(+30.22,+3.75,+2.58) mm`、
cam1 `(-34.85,+3.75,+2.58) mm`；另一组 X 符号与此几何相差约 130 mm。
此判断依赖标定旋转及通道对应关系，并不能独立验证 PCB 轴方向或测量参考点。

两组 PCB 候选坐标之间的差为 `(-65.07,0,0) mm`，与标定双目外参约相差
`(+0.163,-2.124,+0.285) mm`，模长约 2.15 mm。为保留用户给出的两个位置和原始
双目外参，两条相机到 IMU 的路径尚非严格闭合；禁止把该候选值称为准确的最终外参。
重建精度、VIO 漂移和时间对齐仍需实机验证。

Kalibr 的 `T_cam_imu` 表示 IMU 到相机，所以平移写为 `-R_cam_imu @ camera_center_imu`，
不能把 PCB 相机中心直接塞入平移列。ORB 左图实际使用 cam1，`IMU.T_b_c1` 由其逆
变换及极线校正旋转计算。GUI 左图仍是 cam0、通道 4。

本次保留现有 480 Hz、IMU 噪声和格点时间对齐设置；结果 2 的 `data3-imu.yaml` 含
scale-misalignment 模型和不同噪声，当前实时链未验证按该模型修正原始 IMU，不能直接
将它等同已启用或已验证的 IMU 标定。原始 Kalibr 时移也未直接替换实时格点参数。
