# VS030 双通道实时直连

## 使用

1. 相机通过 USB 连接电脑，确保 ADB 设备处于 `device` 状态。本机 ADB 在 `tools/android/platform-tools/adb.exe`；设备序列号、抓流接口和通道参数集中在 `src/egohand/sources/vendor_placeholder.py` 的文件顶部。
2. 关闭 VisionViewer 或其他占用相机 UDP 45680 端口的程序。重启 EgoHand Studio，数据源选择 **VS030 · 双通道预览**，点击“开始采集”。
3. 程序通过 ADB 查询设备 USB 网卡的链路本地地址，然后直接经 USB 网络发送设备控制命令，启动 NET 双路 H.265 并接收 UDP 图像；不需要启动上位机，也不使用设备上的 tcpdump 抓取视频。停止采集会关闭本程序启动的视频流和相机。

两路 H.265 传输通道 4、5 已实测各为 1600×1200 彩色图。用户确认通道 4、5 的左右顺序与 VisionViewer 一致；该确认不等于已验证物理镜头标定方向。两帧来自同一 UDP 数据包组，但没有确认设备曝光时间戳、硬件同步精度和编解码延迟；处理时间是电脑解码完成时的单调时钟，不是传感器曝光时间或准确的网络到达时间。元数据明确标记 `UNVERIFIED`，不伪造左右传感器时间戳。

实时解码完成时间使用 Windows 高分辨率性能计数器，避免低分辨率单调时钟在连续帧上给出重复时间；它仍是主机处理时间。标定已启用而某帧未完成校正时，预览保留上一张校正图并报告错误，不将异常原图插入校正画面。

VS030 启动时自动加载 `标定结果/1/data3-camchain-imucam.yaml`；用户确认 cam0 对应上位机左路 / 通道 4，cam1 对应右路 / 通道 5。Kalibr pinhole + equidistant 使用 OpenCV 四参数 fisheye，`T_cn_cnm1` 是 cam0 → cam1，平移单位为米。输入必须与标定的 1600×1200 分辨率一致。ROI、MediaPipe / RTMPose 和二维点使用同一张去畸变及极线校正后的图；无法加载标定时只显示原图，不运行检测。

本文件也包含 `T_cam_imu`：由 IMU 指向相机；轨迹模块需要 `T_imu_cam`，程序取逆后载入 cam0 变换，不覆盖已经加载的其他轨迹标定。Kalibr 时间偏移为 `t_imu = t_cam + shift`，cam0 约 -0.223781 秒；当前实时视频没有可用的传感器时间戳，也没有把该偏移用于实时 VIO 同步。标定报告的重投影误差均值约 2.15 / 2.10 像素，不能直接作为重建精度。不可用合成、EuRoC 或其他数据集标定代替设备标定。

用户已确认设备左右同步；`configs/stereo.yaml` 中 `vs030_user_confirmed_sync: true` 允许使用同一完整 UDP 数据包组进行三维重建。结果标记 `USER_CONFIRMED_SAME_BUNDLE`，并保留同步精度未实测、左右曝光时间戳不可用的事实；没有将主机时间冒充传感器时间。设备 `/root/scripts/run_all.sh` 会启用 30 Hz PWM，相机触发输出实际处于启用状态，但此检查本身不能证明两路曝光差数值。关闭该配置后重新启动采集可恢复严格同步门控。

检测页提供“三维跨帧 ID 跟踪”开关，切换会清空历史轨迹；关闭后仍逐帧匹配和三角化，但不承诺跨帧 ID。`configs/app.yaml` 的 `vs030_rescue_crops_per_frame` 调整实时每帧每侧补检区域数，默认 1 并轮流覆盖四个区域；较大的值可能改善漏检恢复速度，但增加 CPU 开销。

`configs/stereo.yaml` 的 `min_depth_m`、`max_depth_m` 默认均为 `null`，不按深度距离上下限拒绝；正深度、有限视差、极线、重投影、骨长等检查仍然有效。VS030 的 `vs030_max_epipolar_px` 默认 5 像素，较通用 3 像素更宽，只代表候选门限，并不意味着 5 像素以内的关节精度已得到证实。近距离可能受遮挡、模型偏差和标定误差影响；远距离小视差会放大深度误差，不应把取消距离限制视为所有距离都可靠。

检测页“稳定显示”默认启用，仅平滑预览上的二维关节与三维骨架，原始检测、三角化、误差、录制和数据导出不变；点击三维关节时会标明显示值已平滑。无效点不补造，断帧超时或身份变化会重置；可在 `configs/app.yaml` 的 `display_smoothing` 调节平滑与滞后的权衡。默认三维视角围绕左相机原点，网格固定；手移动不驱动视角，用户仍可主动选择其他旋转中心或鼠标拖动视角。

`scripts/inspect_vs030_calibration.py` 对实时校正图做 SIFT 匹配统计，结果记录于 `results/camera/vs030_calibration_check.json`，不保存画面。抽查 8 组图像的匹配极线误差中位数约 0.77–0.93 像素；这包含错误匹配的影响，也不能替代标定板复验、同步和深度精度测试。

本机项目虚拟环境已安装 `av==19.0.2`。重建环境时在已有项目环境执行 `.venv\Scripts\python.exe -m pip install -r requirements-vendor.txt`，并从 Google 官方渠道重新取得 Android platform-tools。控制命令基于此设备与上位机的实际交互适配，厂家协议及跨设备、跨固件版本兼容性尚未验证；如有官方 SDK，应优先采用官方规范。

## 同步初检与限制

`scripts/inspect_vs030_transport_sync.py` 只统计设备 USB 网卡的 UDP 包头，不保存画面。一次短时采样得到 63 个完整的通道 4→5 数据包组，组起始间隔平均约 33.32 ms；另有一个未完整观察的边界组。数据包组不等于硬件同步帧，包头发送间隔也不是曝光时间差。

`scripts/inspect_vs030_flash_sync.py` 对着两路都能看到的手机闪光采集图像组，仅保存亮度统计、不保存画面。一次 301 组检查中，双路亮度在零组偏移的相关系数约 0.974，在 ±1 组时分别约 0.767 和 0.735，说明采样时两路亮度变化在相同接收组最一致。但接收和解码存在丢组、缓冲和自动曝光影响，不能从这一结果求出曝光时间差或证明硬件同步。此次主机解码完成间隔中位数约 16 ms、P95 约 172 ms，后续需要降低或测量缓冲与丢帧，不能把此时间当成相机时序。

如需验证同步精度，仍需厂家说明曝光触发机制、帧号和左右传感器时间戳的单位及同步时钟；或采用可计时的闪光 / 高速设备独立测量。用户确认提供的是同步依据，不是曝光差的测量数值。
