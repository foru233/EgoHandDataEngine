# 原生世界系修订号 world_frame_revision（2026-11-11）

目标：给桥接层补一条“世界系是否被整体重锚”的原生判据，使 GUI / 审计不再只靠
`map_epoch = map_id<<40 | reset_revision<<20 | big_change_revision` 判断坐标系一致性。
取证背景见 `docs/VIO_27m跳变取证_20261111.md`：那次 27.307 m 跳变期间
`map_epoch` 是 0/0/9 → 0/0/9（完全没变），`map_change_index` 只 +1，所以“epoch 变了
才断轨迹”的逻辑识别不出整图重锚。

实现策略（刻意选低风险路径）：**不改 `System.cc` / `LocalMapping.cc` / `Tracking.cc`**，
全部逻辑放在 `Optimizer::FullInertialBA` 内部，并在求解完成后按同 ID 关键帧做一次
整体 SE(3) 拟合。因此不存在“先声明风险再退一步”的降级：原计划的一条路径就够用。

## 1. 改动点

### 1.1 原生判据与计数器（新增两个文件）

`third_party/ORB_SLAM3/include/VioWorldFrameRevision.h`（纯 Eigen，可脱离 ORB 单独编译）：

- `FitRigid(before, after)`：对**同 ID**关键帧世界位置做 Umeyama 相似变换拟合
  （`after ≈ s·R·before + t`），输出 `t` 的模长、旋转角、尺度与残差 p50/p95/p99/max。
  少于 3 帧、ID 不匹配、含非有限值、或关键帧位置没有空间展开（`variance ≤ 1e-12`）时
  返回 `valid=false`，不做猜测。
- `Decide(fit, thresholds)`：`residual_p95 ≤ max(residual_floor_m, residual_fraction·‖t‖)`
  且 `‖t‖ > min_translation_m` ⇒ `Reanchor`；否则 `TranslationBelowThreshold` /
  `NonRigid` / `InsufficientSamples`。默认阈值 `0.05 m / 0.05 m / 5% / 5 帧`。
- 阈值可用环境变量覆盖（无需重编）：`EGOHAND_VIO_WORLD_FRAME_MIN_TRANSLATION_M`、
  `EGOHAND_VIO_WORLD_FRAME_RESIDUAL_M`、`EGOHAND_VIO_WORLD_FRAME_RESIDUAL_FRACTION`、
  `EGOHAND_VIO_WORLD_FRAME_MIN_KEYFRAMES`；`EGOHAND_VIO_WORLD_FRAME_DISABLE=1` 关闭。

`third_party/ORB_SLAM3/src/VioWorldFrameRevision.cc`：进程级计数器（`std::mutex` 保护），
`Record()` 每次评估 `evaluations+1`，`NonRigid` 时 `rejected_nonrigid+1`，只有
`Reanchor` 才 `revision+1 / detections+1`；设置 `EGOHAND_VIO_DIAGNOSTICS` 时还会把每次
评估追加到 `<诊断目录>/world_frame_events.jsonl`（含 keyframes/verdict/translation/
rotation/scale/残差/limit/revision），便于脱离位姿流单独取证。

计数器必须定义在这个 `.cc`（ORB_SLAM3 静态库）里而不是头文件 inline，否则桥接 DLL
会链接到自己的一份副本、永远读到 0。

### 1.2 挂接点（`third_party/ORB_SLAM3/src/Optimizer.cc`，3 处）

1. `#include "VioWorldFrameRevision.h"`。
2. `optimizer.initializeOptimization()` **之前**捕获同 ID 关键帧位姿
   （`VertexPose::estimate().twb`），条件 `!bFixLocal && !bInit && VioWorldFrame::Enabled()`。
3. `NormalizeGauge` 之后、写回位姿之前重取同一批 ID 的位姿、拟合、`Record()`，重锚时打印
   一行 `VIO world frame re-anchor #N (map M): K keyframes moved X m, rotation R deg, residual p50/p95 …`。

三点设计取舍：

- 只覆盖 `bFixLocal=false`：只有自由规范路径能把整图沿不可观测的世界平移搬走；
  `bFixLocal=true` 时大部分关键帧被固定，同 ID 整体拟合不会报“整体位移”，判据本身也不适用。
- 排除 `bInit=true`：惯性初始化那次 BA 是**建立**世界系而不是搬动既有世界系。
- 放在 `NormalizeGauge` **之后**：`EGOHAND_VIO_GAUGE_FIX=1` 会把坐标系还原，此时判定
  必须基于最终写回的位姿，因此该实验路径不会误报重锚。

### 1.3 桥接层（C ABI，增量扩展）

`src/egohand/vio/native/vio_bridge.h` 新增**独立**结构体 `EgohandVioWorldFrameInfo`
与三个新导出：

```c
int32_t egohand_vio_world_frame_info_size(void);
int  egohand_vio_get_world_frame_info(void* handle, EgohandVioWorldFrameInfo* out, int32_t out_size);
const char* egohand_vio_capabilities(void);   /* "result;snapshot;body_state;recovery_callback;start_new_map;world_frame_revision" */
```

字段：`revision / detections / evaluations / rejected_nonrigid / verdict / last_keyframes /
map_id / last_max_keyframe_id / last_timestamp_sec / last_translation_m / last_rotation_deg /
last_scale / last_residual_p50_m / last_residual_p95_m / last_residual_p99_m /
last_residual_max_m / last_residual_limit_m`，`verdict = -1` 表示还没有任何一次评估
（枚举 0 是 `Reanchor`，未评估绝不能冒充重锚）。

`src/egohand/vio/native/vio_bridge.cpp`：`VioHandle` 增 `world_frame_baseline`，在
`egohand_vio_create` / `egohand_vio_create_map` 中记录当时的 `Revision()`，getter 返回
`revision - baseline`，因此同一进程复用多个 session 时仍按 session 报增量。
`egohand_vio_api_version()` 从 `0.1.0` 升到 `0.2.0`（仅信息性，能力探测以
`egohand_vio_capabilities()` 为准，仓库内没有代码断言该字符串）。

### 1.4 Python 侧：每帧返回并写入 poses.jsonl

- `src/egohand/vio/native_bridge.py`：新增 `_CWorldFrameInfo` ctypes 结构、hasattr 守卫的
  绑定与大小/版本校验、`get_world_frame_info()`；`VioFrameResult` 增
  `world_frame_revision`（int）与 `world_frame_info`（dict，含 verdict/拟合量）。
  旧 DLL 没有该导出时返回 `None`，`world_frame_revision` 退化为 `0`（表示“不支持”，
  不表示“没有重锚”）。
- `src/egohand/vio/live_subprocess.py`：每帧响应增加 `world_frame_revision` 与
  `world_frame`（拟合详情，去掉了重复的 revision 字段）。
- 因此 `poses.jsonl` 每行新增 `world_frame_revision` 与 `world_frame{...}`；
  `PoseQualityGate.check` 用 `dict(result)` 复制，不会丢字段（有测试覆盖）。

## 2. ABI 兼容性说明

- `EgohandVioResult` **字段顺序与大小完全未变**，`egohand_vio_result_size()` 仍与
  Python `ctypes.sizeof(_CResult)` 一致；现有 GUI/Python 不改也能加载新 DLL。
- 新信息走**独立结构体 + 独立 getter**，带 `schema_version`/`struct_size` 与显式长度参数，
  Python 侧先比对 `egohand_vio_world_frame_info_size()` 再解析，不匹配即报错而不是错位读取。
- 新导出是**追加**符号：旧 Python 不认识就 `getattr` 返回 `None` 跳过；旧 DLL 没有该
  符号时新 Python 也照常工作（字段回落 0）。能力串只追加 token，不删除、不改变既有含义。
- 计数器是进程级（一套 ORB-SLAM3 实例），按句柄基线折算成 session 内增量，因此
  不支持“一个进程内两个 System 各自独立计数”——本项目每进程一个 System，够用。
- 新 DLL 名称独立：`egohand_vio_world_frame.dll`。`native/bin/active_bridges.json` 不存在，
  `library_manifest.select_library` 的 live 默认仍是 `egohand_vio_recovery_bridge_v9.dll`，
  **不设置 `EGOHAND_VIO_LIBRARY` 就不会生效**，既有产物与配置零改动。

原生测试覆盖的判据行为：

1. 75 帧整体平移 22.82 m（叠加 1 cm 噪声）→ `Reanchor`，`scale≈1.0`，残差 p95 < 0.05 m；
2. 同 ID 关键帧各自独立抖动 2 cm（无共同位移）→ `TranslationBelowThreshold`，**不**计重锚；
3. 每帧独立散开 10 m（大位移但非刚性）→ `NonRigid`，**不**计重锚（`rejected_nonrigid+1`）；
4. 0.10 m 刚性位移 + 1 mm 噪声 → `Reanchor`（阈值下界处仍能识别）；
5. 3° 旋转 + 1 m 平移 → `Reanchor`，拟合旋转 3.0°；
6. 只有 3 帧、平移 10 m → `InsufficientSamples`，**不**计重锚；
7. ID 不匹配、无空间展开的点云 → `valid=false`（拒绝而不是瞎猜）；
8. `Record/Revision/Reset`：只有重锚会 `revision+1`，抖动只增加 `evaluations`。

### 5.1 主结果：在第 964 行检出重锚，位姿流上的 35.5 m 跳变出现在第 1082 行

`worldframe_final`（1727/1727 帧，`error=null`，worker 退出码 0）：

| 量 | 值 |
| --- | --- |
| 检出位置 | **poses.jsonl 第 964 行 / frame 963** |
| `world_frame_revision` | **0 → 1**（全程唯一一次递增） |
| `map_epoch` 该行 | **8 → 8（未变）** |
| 同 ID 关键帧 | 42 |
| 拟合整体平移 | **36.012 m** |
| 拟合旋转 / 尺度 | 5.26° / 0.931 |
| 残差 p50 / p95 / max | 0.0234 / **0.1218** / 0.1448 m |
| 判据上限 `max(0.05, 5%×36.012)` | 1.8006 m → 残差远小于上限 |
| 该行位姿步长 | 0.042 m（此时位姿流**还没动**） |

位姿流上的大跳变随后才出现，且全程只有这一处 > 1 m：

| poses.jsonl 行 | frame | 步长 | 旋转 | `jump_detected` | `map_epoch` | `world_frame_revision` |
| ---: | ---: | ---: | ---: | --- | --- | --- |
| **1082** | 1081 | **35.523 m** | — | **True** | 9（与 1081 行相同） | 1（已在上游置位） |

第 1081→1082 行的 raw 位姿平移从 `[11.343, 14.040, 5.390]` 变为
`[20.661, 30.279, 35.579]`，即约 35.5 m 的整段位移。

**与取证文档第 1080 行 27.307 m 的关系**：同一个现象、同一类位置。参考运行
（`pair2_20261111_171149`，旧 DLL）在**第 1080 行**记到 27.307 m 且 `map_epoch` 9→9；
本次运行在**第 1082 行**记到 35.523 m。帧号相差 2 行、量级同属“几十米整图位移”，
差异来自 ORB-SLAM3 多线程的 run-to-run 不确定性。关键是：**这次 `map_epoch` 同样不足以
标识它**——重锚发生在 epoch 8 内（8→8），而可见跳变在 epoch 9 内（9→9），两处 epoch
都没变；`world_frame_revision` 是唯一把这个事件单独标出来的信号，并且比可见跳变**早 118 行**
（即“重锚由全 BA 造成，位姿流随后才被搬到新基准”），这正好解释了为什么按位姿步长做统计
只能事后发现、而按修订号可以在 BA 当帧就知道。

同一目录的 `native_diagnostics/world_frame_events.jsonl` 是脱离位姿流的独立取证：

### 5.2 另两次运行：判据在“没有重锚”时保持安静

| 运行 | 全 BA 评估 | 判定 | 平移 | 残差 p95 / 上限 | `world_frame_revision` | 位姿流 >1 m 步长 |
| --- | --- | --- | ---: | --- | --- | --- |
| `worldframe_final` | 1 | **reanchor** | 36.012 m（42 帧） | 0.1218 / 1.8006 | **1**（第 964 行） | 第 1082 行 = 35.523 m |
| `worldframe_inertial` | 1 | **reanchor** | 52.774 m（51 帧） | 0.1179 / 2.6387 | **1**（第 976 行） | 第 1011 行 = 54.735 m、第 1530 行 = 43.099 m |
| `worldframe_inertial_diag` | 1 | **non_rigid** | 0.270 m（52 帧） | 0.1766 / 0.05 | **0** | 无 |

读法：

1. 三次运行里自由规范全 BA 各只发生 **1 次**，说明该路径稀疏但后果巨大——正好符合
   “一次求解把整图搬走”。
2. 判据在 36 m / 52.8 m 两次真重锚上都触发（残差 0.12 m 远小于位移的 5%），在
   0.27 m 的非刚性调整上**没有**触发（残差 0.177 m 超过 0.05 m 下限，且位移本来就小）。
3. `worldframe_inertial` 里第 1530 行的 43.099 m 步长没有伴随新的全 BA 评估——它不是
   自由规范全 BA 造成的，见“已知局限”。
4. `scale` 为 0.85–0.93 而不是 1.0：本次重锚**不是纯刚体**，同时带了 7%–17% 的尺度变化。
   判据只看“残差小 + 位移大”，尺度和旋转只作审计输出，这是有意的（尺度突变同样属于
   世界系变更，不应被漏掉），但也意味着“纯刚体”不是它的前提。

## 6. 已知局限

1. **只覆盖 `FullInertialBA(bFixLocal=false)`，且跳过 `bInit=true`**。`Optimizer::LocalInertialBA`
   （`LocalMapping.cc:155`）、重定位/`ResetActiveMap`、回环 GBA 的延迟应用都不在计数范围内。
   实测中 `worldframe_inertial` 第 1530 行的 43.099 m 步长就没有对应评估，属于这类未覆盖路径。
   同一重锚的“延迟应用”虽然不重复计数，但已被上游那一次递增提前标出（本次提前 118 行）。
2. **只拟合关键帧的 body 位置**，不看地图点、速度、重力方向。取证文档显示同一次事件里地图点
   被拉到公里级，因此“残差小”只能说明**关键帧**被整体搬动；点畸变需要另外的判据。
3. **阈值是启发式**，不是验收结论：0.05 m / 5% / 5 帧只是把“整图搬动”与“逐帧抖动”分开。
   关键帧少、点云窄、或位移恰好在 0.05 m 附近时可能不判定；环境变量可现场调整。
4. **计数器是进程级**：一个进程内多个 `System` 会共用同一个 revision（按句柄基线折算增量）。
5. **run-to-run 差异明显**：同一录制三次运行分别出现 36 m、52.8 m 与“没有重锚”，
   因此“某个特定帧号必须递增”不能当验收条件；能否复现的判据应是“整图重锚发生时被标出来、
   没发生时保持安静”，本次三次运行都满足这一点。
6. GUI 生效方式：新 DLL 不会被自动选中（默认仍是 `egohand_vio_recovery_bridge_v9.dll`），
   需要 `EGOHAND_VIO_LIBRARY=...egohand_vio_world_frame.dll`（或写 `active_bridges.json`）
   并**重启 GUI / live worker**；已经加载旧 DLL 的进程不会热切换。
