## 2. 判读

**n=2 时看起来"方向对"，扩到 n=5 后差异消失**：

1. OFF 组的 4 次完整运行：同段 >0.5 m 分别 21 / 1 / 1 / 10 次，`>1 m` 重锚 10 / 0 / 0 / 4 次；ON 组 5 次：5 / 2 / 1 / 14 / 8 次，重锚 0 / 1 / 0 / 3 / 2 次。两组中位数（5.5 vs 5.0、2.0 vs 1.0）差异远小于组内波动。
2. OFF 组最差一次（off_run5）出现 **53.34 m** 同段位移，ON 组最差（on_run4）14 次异常、on_run2 有 11.39 m —— **两组都会崩，只是崩的位置不同**。
3. 因此 **`EdgeWorldGauge` 在这批数据上测不出效果**。之前"5 次 + 2 次 vs 21 次"的印象来自 n=2 的偶然抽样（off_run2 恰好是最差的一次）。
4. `off_run1` 以 `TimeoutError` 在 838 帧中断，不计入统计；`on` 组 5 次全部完整。

## 3. 结论（可对外表述）

- **实验 C（`EdgeWorldGauge`）在当前录制与样本量下无法证明改善稳定性**：两组同段异常中位 5.5 vs 5.0、`>1 m` 重锚中位 2.0 vs 1.0、最大步长中位 1.81 vs 2.08 m，区间完全重叠。
- 这**不等于**"规范自由度假设错误"：取证已经证明那 22.82 m 的整图平移确实发生在 `FullInertialBA` 内部且落在零空间方向（见 `docs/VIO_跳变根因取证总报告_20261111.md` 第 2.2/2.3 节）。更可能的解释是：约束只处理了"解后坐标选择"的一部分，而跳变的主要来源还包括地图点畸变与调度不确定性。
- 若要判定实验 C 是否有效，需要：固定调度/线程数、每组 ≥10 次、以"`world_frame_change` 计数"为主要指标（而非同段 >0.5 m 这种会被其它抖动污染的指标）。

## 4. 限制

- `off_run1` 为超时中断样本，不可与完整运行并列统计。
- 各组为独立进程串行运行，但宿主同时有其它构建/测试负载，不能把 `track_ms_p50` 差异解释为算法性能差异。
- 本实验不涉及绝对精度（无真值），只比较稳定性指标。
- 指标本身混合了"整图重锚"与"帧间抖动"两种现象；建议改用 `scripts/audit_world_frame_changes.py` 的 `world_frame_change` 计数作为主指标（已实现，见 `docs/世界系变更检测_20261111.md`）。
