# VS030 VIO 交付复核（2026-11-12）

本次以最新交付口径为入口，读取问题总账、NaN 加固、原生世界系字段及现行源码，并核对此前完成的实验产物；不重复门限、止血、剪枝等已否决实验，不改默认 DLL 或开启实验开关。

## 已发现并修复的消费缺口

`world_frame_revision` 虽已由新库输出，质量门控、GUI 轨迹和预设地图身份此前仍仅消费 epoch。同 epoch 整图重锚会被当成连续世界系。现增加公共 `world_identity`，联合 epoch/revision：

- 质量门控重新等待稳定，保留原始矩阵，不把跨世界位移当作真实运动。
- GUI 清理旧世界轨迹并重新适配，原始对比也按世界身份分段。
- 预设地图在已定位后发生世界修订时暂停叠加、差异和更新，要求重新载入。
- 旧库缺修订号时保持旧行为，不将不支持冒充“没有重锚”。

文件：`map_identity.py`、`pose_quality.py`、`gui/vio_panel.py`，以及两项新增世界身份消费测试。相关原有25项测试已通过，最终全量记录见 `logs/vio_delivery_review_20261112.log`。

## 必须保留的交付限制

SafeExp 的 `ok=false` 尚未被 `ImuTypes.cc` 调用路径消费；无效输入退回旧旋转可能继续参与优化。已完成的12项数学/防崩测试和单次完整回放不能证明失败位姿可信。此次不把该库部署为默认，也不在没有端到端证据时改动预积分 ABI 或大范围优化路径。交付清单已更正“建议直接替换”和“唯一稳定性风险”的表述。

全局优化畸变、地图点深度发散、时间物理语义及实机长期精度仍未验收。规范约束虽有原生几何证据，仍默认关闭；不重新启用无显著收益的门限/止血/剪枝。

## 既有结果不重跑

`stability_baseline/long_3200_snapshot/experiment.json` 已记录3200帧完成、退出0。此前 Atlas 导入及导出重载产物、黑帧、纯双目/惯性及重复回放记录均保留在 `results/vio/stability_baseline` 和对应日志。它们证明各自数据/库版本的执行结果，不能移作 SafeExp 或最新所有实验库的整体稳定性证明。

结论：可以交付已验证的配置与诊断工具及本次世界身份消费修复；不能签署“VIO 稳定性根治”验收。默认配置、词典生命周期、原始数据及已有 DLL 保持原部署选择。

关闭 depth gate、point clamp、entry prune、解后 gauge fix；SafeExp 暂未启用，原因是其失败状态尚未传播到可信度准入。GUI/地图/质量及部署相关回归36项通过。完整 GUI 测试首先遇到本机屏幕/DPI限制导致窗口不能达到要求尺寸；原始日志 `vio_delivery_review_20261112.log` 和缩放对照日志保留，不把它算作全量通过。

切换后必须重启 GUI/live worker。此部署是用户授权启用的规范约束候选，不能替代实机长跑与精度验收。
