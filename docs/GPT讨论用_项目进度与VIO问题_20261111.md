## 1. 希望讨论什么

当前优先问题是 VS030 双目惯性定位出现明显位置跳变，用户体感跳变后可能更稳定。需要判断跳变究竟是全局坐标变化、优化退化、地图畸变、跟踪恢复错误，还是配置/标定/时序问题，并设计能区分这些原因的实验。

请先审查下述证据和推理，不要直接把任何假设当成已确认根因。讨论建议和代码修改应分开，尤其不要通过平滑、重置显示原点或放宽门限掩盖原始异常。

## 2. 项目目标与架构

项目在 Windows 上使用 VS030 双目相机及 IMU，现有 GUI 同时处理相机预览、双目手部识别、三维重建和实时 VIO。另有独立环境扫描程序 `map_creat`。

最终目标包括：

1. 扫描时实时显示左右图、轨迹和粗点云，停止后以最终地图位姿完成精细融合。
2. 导出可重定位的 ORB-SLAM3 Atlas、PLY 点云，以及区分占据、空闲、未知的空间数据。
3. 现有 GUI 导入地图后，确认位于旧地图坐标系才能叠加轨迹与差异。
4. 人和运动物体显示临时黄色；多视角确认新增显示蓝色；看到旧表面后方后才确认移除并显示红色。
5. 默认只读。允许把确认的静态变化另存新版，保留原地图。

大致链路：VS030 SDK → 双目校正及相机/IMU 对齐 → 独立 ORB-SLAM3 工作进程与 C ABI 原生桥 → 位姿门控/恢复检查 → GUI。扫描实时预览复用部分共享模块，停止后的 Atlas 建图与点云融合有独立流程。

GUI 左目为 cam0/通道 4，右目为 cam1/通道 5。ORB 使用交换后的左右顺序，ORB 左为 cam1，输出需要变换回 GUI 左相机坐标定义。

## 4. 当前标定与时序

GUI 当前采用标定结果 2 的候选配置：

- 标定：`标定结果/2/data3-camchain-imucam-measured.yaml`。
- ORB：`configs/vio/vs030_rectified_half_calibration2.yaml`。
- 输入缩放 0.5，ORB 图像为 800×600。
- `imu_alignment=lattice`，`lattice_reference=packet`，IMU 480 Hz，包头格点相位 +97 ms，漂移修正 0 ppm。
- 文件中同时保留 `camera_to_imu_lag_ms=-85`，不能把旧时间戳模式的此值与当前包头格点相位简单相加。

相机光心在 IMU 坐标系下的候选位置（mm）：cam0 `(+30.22,+3.75,+2.58)`，cam1 `(-34.85,+3.75,+2.58)`。当前 X 符号来自现有双目外参、旋转及通道对应关系，尚无独立物理真值确认。两组实测中心与原双目几何存在约 2.15 mm 闭合差。

录制 A/B 仅改变右目 X 符号，两段各 450 帧的有效位姿分别为 338 对 343、358 对 358，差别不足以判定物理方向。结果 2 的 IMU scale-misalignment 模型尚未在实时链路验证启用，不能说 IMU 全部标定项已经接入。

必须区分：双目基线提供米制尺度；BA2 完成不等于“此前是无米制的单目尺度”，也不证明定位准确。当前字段 `inertial_scale_finalized` 实质对应 BA2 完成状态，旧代码注释曾将其解释过度。

## 7. 最新跳变的证据

数据源：`logs/vio_vs030_live_1794365340784986200_poses.jsonl`，已分析快照为 863 条、63.1 秒。对应常驻进程日志为 `logs/vio_vs030_worker_1794365009983077600.log`。下表时间相对会话第一帧，位置来自 GUI 左相机的原始矩阵。

| 时间 | 位置或事件 | 状态变化 |
| --- | --- | --- |
| 36.967 s | (-0.774,0.167,0.155) | IMU 已初始化，BA2 未完成 |
| 37.067 s | (-0.694,-1.249,0.563)，变化约 1.475 | 地图修改版本增加 |
| 54.767 s | (-0.535,-1.242,-0.291) | BA2 未完成 |
| 54.833 s | (-128.053,153.576,-196.182)，变化约 280.363 | BA2 完成，地图修改版本增加 |
| 59.900 s | 进入异常隔离 | 暂停可信输出 |
| 62.967 s | 恢复超时，重置当前地图 | IMU 与 BA2 标志清除 |
| 63.000 s | 新位置接近 (0.065,0,0) | 新地图等待初始化 |

该会话原生日志有 `start/end VIBA 1`、`start/end VIBA 2` 和之后的 `Recovery timeout: starting a new map`，没有对应的重定位、闭环或地图合并记录。主跳变时地图 ID 未变，大修改计数改变。

当前 `pose_continuity:false`，没有启用显示重锚。GUI 在地图 epoch 改变时会清空旧轨迹并重新适配视图，这会影响用户对位置与缩放的观感，但原始矩阵本身也确实变了。

### 可以确认与不能确认的区别

**可以确认**：主跳变与 VIBA2 优化结果发布、地图版本更新同刻发生，不能归咎于单纯绘图。后续定位仍未持续可靠。

**强嫌疑，待验证**：全局优化未固定世界原点，平移自由度可能造成优化后整体坐标大幅迁移。

**尚未证明**：280 米完全是无害的刚体平移；固定原点一定解决所有跳变；最新标定或时序就是唯一根因；跳变后精度提高。

### 原点自由度假设的代码依据

`third_party/ORB_SLAM3/src/LocalMapping.cc` 中 VIBA2 调用 `InitializeIMU(0,0,true)`，随后调用 `FullInertialBA`，其 `bFixLocal=false`、`bInit=false`。

`Optimizer.cc` 的 `FullInertialBA` 创建位姿顶点时，仅在 `bFixLocal` 分支中调用 `VP->setFixed(...)`；当前全局路径没有固定原点关键帧，也未见世界位置先验。相对视觉和 IMU 约束不能观测整体平移，这提供了坐标漂移机制。但自由度本来就可能存在于 SLAM 优化设计中，不能仅凭此认定是此次数值异常的唯一缺陷。

`LocalMapping.cc` 随后写回优化后的关键帧和地图点。由于没有保存同 ID 地图元素的优化前后快照，当前无法区分纯刚体变换与几何畸变。需要检查实际编译版本、约束图以及优化残差后再下结论。

## 8. “跳变后更稳定”是否成立

从原始相邻矩阵统计，排除 epoch 跨界，得到：

| 区间 | 门控有效输出 | 原始步长 P95 | 原始速度 P95 |
| --- | --- | --- | --- |
| 主跳变前一小段 | 67/88 | 0.0748 m | 1.259 m/s |
| 主跳变后一小段 | 28/72 | 0.0640 m | 1.044 m/s |
| 后续隔离段 | 0/74 | 0.0892 m | 1.756 m/s |

跳变后短段的大步长减少，与体感可能一致。但运动不相同、无独立真值、有效输出占比没有改善，不能据此认定噪声或定位误差降低。优化重新估计偏置/重力后局部运动更平顺，以及视图重置带来的观感变化，都是可能解释。

## 9. 请 GPT 重点讨论的问题

1. 当前证据能把因果链确认到哪一层？“VIBA2 发布结果”与“优化为什么错”应如何区分？
2. 全局平移及航向自由度应如何处理？固定完整首帧六自由度、只固定不可观测自由度、软先验、优化后统一规范坐标，各有什么风险？如何避免妨碍重力方向优化？
3. 如何用同 ID 关键帧/地图点的前后快照、SE(3)/Sim(3) 拟合残差、成对距离及重投影误差，区分整体换坐标、尺度变化和非刚体畸变？应采哪些日志？
4. 双目米制条件下，BA2 前后的尺度与初始化状态应该怎样表述和门控？仅有 BA2 完成标志是否足够允许扫描或建立 IMU 外推锚点？
5. `map_epoch` 是在 TrackStereo 返回后另读的，后台优化又会更新地图。应否检查矩阵、地图版本和 body state 是否来自同一原子快照？如何设计一致性接口？这只是待检查项，当前未证明已发生竞态。
6. 同 epoch 内的小跳变，需要哪些特征匹配数、双目深度、局部 BA 修正量及 IMU 残差，才能判断是视觉误匹配、局部优化还是时序/标定问题？
7. 扫描和 GUI 的配置应怎样统一，同时可靠保留历史录制快照、词典复用及 Atlas 兼容性？
8. 按风险与信息收益，最小验证顺序是什么？哪些可用录制重复实验，哪些必须实机和独立测量？

建议讨论输出包含：已确认事实、按证据排序的根因假设、每个假设的支持/反对证据、最小 A/B 实验、量化验收标准、可能破坏现有功能的风险。请不要仅凭跟踪有效帧数或“看起来平滑”评价精度。
