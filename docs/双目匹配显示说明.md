# 双目手部匹配与画面颜色

算法预测模式下，相同彩色与相同 `#编号` 表示当前帧被双目关联接受、且身份跟踪没有被拒绝的同一条轨迹；颜色根据轨迹编号分配，不代表生理左手或右手。黄色 `unmatched` 表示该视图观测当前没有有效的已接受轨迹，不应根据黄色相同推断已经匹配。`Left` / `Right` 仍是模型对手侧的原始预测，可在左右视图不同；RTMPose 未提供该分类时显示 Unknown。红圈表示该已关联手的对应关节被几何门控拒绝。GT/合成模式保留各自原有颜色约定。

图片无法证明具体帧有错误的三维关联。对相似的 SHOW3D 场景 ASC023/balandabowl_stirring_d06c，在 0–300 帧每 5 帧抽取一帧，共 61 帧（无 ROI，MediaPipe 检测阈值 0.2），以官方 v3 UmeTrack 投影按现有 80px / 10px 门限分别事后匹配两视图：15 个已接受配对均能判定身份且左右对应同一真值手。第 55、290 帧可见同一只手在两路手侧标签不一致但未接受配对。该结果不是用户截图确切帧，不代表更大样本不会错配；原始记录见 `logs/show3d_matching_sweep.log`。GT 只用于事后核对，不进入匹配。

本次修改解决显示颜色与模型左右手标签混淆，保留原有几何/歧义门控和输出；没有通过放宽门槛强制配对。现有手侧分类依然可能出错，成功配对也不保证绝对正确。需要调查具体错误帧时，可暂停并在调试页复制本帧 JSON，检查候选、拒绝原因、接受的索引和 GT 对照。
