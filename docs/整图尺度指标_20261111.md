# 整图尺度指标：把"远点多"与"整图被放大"分开（2026-11-11）

配套：`docs/远点深度门限_5x2对照结果_20261111.md`、`docs/地图点止血_5x2结果_20261111.md`、`docs/远点门限倍率扫描_20261111.md`
工具：`scripts/analyze_map_scale.py`

---

## 1. 为什么需要这个指标

之前所有远点相关对照都用 `>50 m` 点数作主指标，后来发现它在某些运行里**等于事件6 的总点数**（如 50× 的 1008/1008、888/888）。这有两种完全不同的解释：

- (a) 剩下少量远点，但都远超 50 m；
- (b) **整张图的尺度被放大**，导致几乎所有点都超过 50 m。

两者对"修复"的指向完全不同，必须分开。

## 2. 指标定义（对整图平移不变，因此不受重锚污染）

| 指标 | 定义 | 性质 |
| --- | --- | --- |
| `kf_spread_p50/p95` | 关键帧到其质心的距离分位 | 对整体平移**不变**；反映跟踪几何是否合理 |
| `pt_spread_p50/p95` | 地图点到其质心的距离分位 | 对整体平移**不变**；反映地图点是否被拉开 |
| `growth.point_spread_ratio` | 同一事件内 `solved / before` 的 spread p50 比 | **单次求解把地图放大了多少倍** |

关键点：`spread` 用**质心**而非坐标原点，所以整图刚体平移（22.82 m 那种）不会污染该指标。

## 3. 结果：关键帧正常，只有地图点被拉爆

`results/vio/depth_gate_multirun`（关闭/开启门限各 5 次，1200 帧）：

| 事件 | 点 spread p50 放大倍数（前→后） |
| --- | --- |
| event2 | **0.82–1.17×**（几乎不变，正常） |
| event4 | 0.59–3.14×（轻微） |
| **event6** | **5.56× – 145.83×**（灾难性） |

而**关键帧 spread p50 在所有 10 次运行、所有事件里都在 0.059–0.252 m 之间**（桌面尺度，完全正常）。

### 3.1 这条数据直接改变了结论

- **不是"整图尺度被放大"**：关键帧几何一直是正常的 6–25 cm 量级；
- **是"地图点相对关键帧被拉爆"**：event6 一次求解把点云 spread 从约 2 m 拉到 12–300 m，放大约 **36–146 倍**；
- 所以 `>50 m` 计数在那些运行里等于总点数，是 (b) 的**表象**，真实情况是**点云整体崩坏**，而非"剩下一堆远点"。

### 3.2 门限臂的对比（仍不能宣称有效）

| 臂 | event6 点 spread 放大倍数 | 中位 |
| --- | --- | --- |
| OFF（5 次） | 36.3 / 64.0 / 77.6 / 87.3 / 107.6 | **77.6×** |
| ON（5 次） | 5.6 / 28.1 / 39.1 / 75.6 / 145.8 | **39.1×** |

中位从 77.6× 降到 39.1×（约一半），**但区间严重重叠**（ON 有 145.8× 比任何 OFF 都差）。→ 方向一致但**不显著**，与此前 5×2 的结论一致。

## 4. 对根因的另一条重要证据

**关键帧几何正常、地图点崩坏**，这个组合强烈指向：求解把**地图点顶点**推到了远离其真实位置的地方，而位姿没有被同步拉走 —— 也就是**地图点与位姿之间的约束（EdgeStereo/EdgeMono）在这些点上失效**，而不是整个解算框架崩了。

这与之前的两条独立证据一致：
- 发散是**纯深度方向**的（\|cos\| 中位 1.000）；
- 这些点在**三角化阶段就已经是远点**（73–118 m）。

→ 结论收窄为：**远点的深度方向几乎没有约束力，BA 可以把它们推到任意远，而关键帧位姿不受影响。**

## 5. 建议

1. **把 `map_scale` 指标作为所有远点相关实验的主指标**，`>50 m` 计数只作辅助。
2. 重跑三档倍率扫描时用它，每组 ≥5 次。
3. 若要继续攻根因，方向应明确为：**给远点的深度方向加约束**（深度先验边 / 或按 `mfMaxDistance` 硬性剔除深度异常的观测），而不是继续调整入口阈值。
