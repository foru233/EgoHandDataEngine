# 性能实测报告

2026-11-03 10:06（Asia/Shanghai）。原始数据 `logs/performance.json`；脚本 `scripts/benchmark.py`。
Windows11、i7-13700KF（16核24线程）、31.84GiB RAM、RTX3050 6GiB。Python3.12.15、MediaPipe0.10.21、OpenCV4.11.0.86。
本次推理使用 CPU。GPU 存在不等于 GPU 推理已测试。

## 合成几何（不运行神经模型）

640×480 双视图，180 帧 crossing，双手 7560 个有效关节观测。

| 指标 | 实测 |
|---|---:|
| 读取/生成平均耗时 | 2.815 ms |
| 处理平均耗时（校正、匹配、三角化、验证） | 3.415 ms |
| 匹配与三角化平均耗时 | 1.990 ms |
| 匹配与三角化 P95 | 2.227 ms |
| 顺序完整循环吞吐 | 157.27 FPS |
| 读取单独容量倒数 | 355.23 FPS |
| 处理单独容量倒数 | 292.82 FPS |
| 最大真值误差 | 1.5790e-15 m |
| 峰值进程 RSS | 410.04 MiB |

单独容量倒数不能与完整循环 FPS 混用。无噪声误差衡量代数实现与数值一致性，不是实机测量精度。
含 0.25px 噪声另有测试：根据 `sigma_Z ≈ Z²/(f*b)*sqrt(2)*sigma_px` 检查合理误差，不承诺固定毫米级准确性。
内存统计包含基准脚本为后续写盘保留的 180 对图像，不代表只保留有界实时队列时的最低占用。

## GUI 与队列

原生 GUI 单次证据约 21.92 FPS，采集交付到处理完成的软件延迟 3.91ms，处理队列0、丢帧0。
该延迟不含硬件曝光/传输、显示器扫描或完整运动到显示延迟。
默认处理队列2；录制队列32；UI 最新预览邮箱1；结果缓存600。
自动测试使用刻意减慢推理和高频输入，确认实时推理丢帧可统计且原始25帧均保存；离线18帧无主动丢弃。
GUI 显示左右检测耗时倒数、匹配/三角化、处理 FPS、软件延迟、队列、丢帧、录制队列/吞吐与进程 RSS。

结论限于本机、这些配置和上述合成/单图输入。未来真实相机需按实际分辨率、曝光、同步、运动速度、图像纹理和磁盘持续负载重测。
