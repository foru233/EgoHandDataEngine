# MANO 拟合与显示

三维窗口的 MANO 菜单有两个独立开关：预测 MANO 为橙色半透明表面，官方真值 MANO 为紫色线框。骨架和原有真值点开关保持独立。MANO 运行在独立 Python 进程，状态与失败原因显示在底部状态栏；遇到缺失模型、手侧不明确、关节不足或拟合残差过大，不生成虚假网格。

预测使用当前有效的左相机坐标三维骨架；即使关闭极线与重投影误差门控，仍可参与拟合，但保留三角化其他基本有效性检查和 MANO 自身质量门控。优化使用关节距离、姿态与手形正则，以及同一轨迹相邻帧姿态约束。MediaPipe 拇指 CMC 没有明确的 MANO 对应，不用于拟合；其余 20 点按照官方 HOT3D MANO 映射，指尖使用 DexYCB 官方 manopth 的顶点。不同体系的关节并不保证完全解剖等价。

当前官方真值 MANO 支持 DexYCB 和已下载官方 MANO 标注的 SHOW3D 场景。DexYCB 读取同帧左相机的 `pose_m` 和受试者 `betas`，按官方 manopth 的 45 维 PCA、平均手形与米制平移生成。SHOW3D 使用官方 `hand_pose_mano.json`、`profile_mano.json` 和官方 ManoMesher 生成世界坐标网格，再转换到原始左相机坐标。模型顶点未经对齐或缩放。其他来源若只有关节点，没有可解析的 MANO 参数，则不显示 MANO 真值，不用骨架拟合结果冒充真值。

拟合在后台逐帧计算。为避免将旧帧网格叠到新帧上，播放快于拟合时会丢弃过期结果；暂停或单帧操作可以查看与当前骨架严格对应的网格。计算耗时依机器而定，不保证实时。

参数集中在 `configs/mano.yaml`。`python` 指向已安装 PyTorch 的解释器，`models` 指向用户自行从官方渠道获取的左右手 MANO 文件目录；`tools/mano_deps` 保存隔离的 smplx、NumPy、SciPy 和 Chumpy 兼容依赖。该路径是本机配置，换机器时需要调整。MANO 模型使用应遵循模型包中的许可证。
