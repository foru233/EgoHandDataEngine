# 主要参数与中文代码注释导航

常用参数已集中放到 `configs/stereo.yaml` 前部：优先关联/歧义、其次几何门控、跟踪、最后不确定性。所有原有默认值保持，未更改算法、界面或评测结论。源码新增中文注释解释处理顺序、坐标系、单位、拒绝条件和来源边界。

## 从哪里改，什么时候生效

|入口|用途|生效范围|
|---|---|---|
|`configs/stereo.yaml`|左右手匹配、三角化、跟踪、不确定性|创建/重启 EgoHandEngine 时加载；GUI 需停止后重新启动采集|
|`configs/detector.yaml`|手数、三个 MediaPipe 阈值、模型路径|GUI 启动时加载；已有模型实例不随文件修改自动更新。界面内修改需点击应用|
|`configs/app.yaml`|处理队列、录制队列、合成源帧率、启动主题|GUI/worker 创建时加载；mode/scenario 初始化控件，运行中以界面选择为准，source 目前为保留项|
|`scripts/run_stereo_benchmark.py --help`|数据集、片段、帧数、模式、输出、配置路径|独立评测命令；`--config` 为 stereo 参数；`--detector-config` 默认读取 configs/detector.yaml（含 0.2 检测阈值与 rescue），并在 detector_snapshot.json 中记录实际生效值|

Engine 接口的 `config` 参数覆盖 YAML 同名顶层项；`uncertainty` 的局部字段另有默认回退。独立直接创建 MediaPipeHandDetector 时以构造函数参数为准；标准 benchmark 现在默认读取 configs/detector.yaml，或者通过 --detector-config 指定独立配置，具体实际生效值以每次新输出目录下的 detector_snapshot.json 为准。旧结果不会被追溯改变。

改参数后保存新输出目录，并核查 `config_snapshot.yaml`/录制manifest 中的实际配置。历史结果不会因修改当前配置而自动变化，之前的 GPT 讨论 ZIP 也保留原快照。

## 第一组：关联与歧义

|参数|默认|含义与方向|
|---|---:|---|
|unmatched_cost|4.0|每侧立体检测选择不匹配的代价。增大通常更倾向于配对；减小更容易保留未匹配。左右各放弃一次，总代价为8.0|
|ambiguity_margin|0.15|最佳全局分配与替代分配的代价差门限。增大更保守，更容易拒绝身份/对应歧义；立体关联和跨帧 ID 都使用它|
|min_valid_joints|8|一只手形成有效候选/轨迹所需的最少有效三维关节数。减小可增加覆盖，也可能接受结构不完整的误配|
|weights.epipolar|1.0|极线残差惩罚权重|
|weights.handedness|0.3|模型左右手标签冲突的软惩罚；并不是硬性强制标签一致|
|weights.temporal|0.7|候选中心到历史轨迹的归一化距离惩罚|
|weights.geometry|1.0|有效关节覆盖损失的惩罚|
|weights.disparity|1.0|仅保留旧配置兼容；当前不参与代价加权，不能靠改它调整匹配结果|

几何硬门控拒绝的候选不会因 unmatched_cost 增大而恢复。`unmatched_cost`也不控制跨帧ID分配中的固定新建代价1.5；后者在 `HandTrackManager.assign()` 中已单独中文标注。`ambiguity_margin`是代价差，不是成功概率或百分比。

## 第二组：像素、深度与同步

- `max_epipolar_px=3.0`：校正后非视差轴的坐标差；增大通常保留更多点，也可能放过错误对应。
- `max_reprojection_px=3.0`：左右重投影误差较大值上限；重投影接近零也可能有厘米级系统偏差。
- `min_disparity_px=0.25`：绝对视差下限；增大可排除更低视差的风险点，同时损失远处关节。
- `min_depth_m=0.15 / max_depth_m=2.0`：引擎当前左光学坐标 Z 范围，不是从相机中心到点的欧氏距离。HOT3D 在虚拟左相机帧中门控，正式导出再转回原生左相机，不能把两个 Z 直接混用。
- `max_sync_error_ms=5.0`：左右记录时间戳的软件容差，不是实测硬件同步精度；放宽它可能引入低重投影但高三维偏差的动态结果。

## 第三组：跟踪

骨长用米；速度用米/秒；时间间隔用秒。允许位移通常按 `max_speed_m_s × dt + temporal_slack_m` 形成。`track_timeout_s` 仅决定旧轨迹保留多久，不保证能正确恢复身份。

超过 `reacquisition_gap_s` 的重现还需要至少两次历史、中心预测残差 `reacquisition_prediction_m` 和去除平移后的姿态差 `reacquisition_pose_rms_m`。放宽这些值可能增加旧 ID 误恢复；歧义仍应显式拒绝，不能把新建ID当成连续跟踪。

## 第四组：不确定性

默认 `enabled=true, mode=diagnostic`，只输出条件协方差；仅 `mode=reject` 才按 `max_depth_std_m / max_position_std_m` 额外拒绝。`assumed_pixel_std=1.5` 是假设，不是实测MediaPipe像素精度。position_std取最大协方差主轴标准差，depth_std取当前输出坐标的Z标准差。

`jacobian_step_px`、`stability_rtol`、`max_jacobian_condition` 是数值稳定性参数，通常在排除像素/标定问题后再检查。不要靠放宽数值条件把退化点标成可靠点。详见 UNCERTAINTY_MODEL.md。

## 排查顺序

1. 看左右 `detected_hands_*`。双路没有同帧检测时，先查检测输入、图像方向/灰度域/遮挡；改 unmatched_cost 或重投影阈值不能补出上游缺失观测。
2. 看 `association_quality.candidates` 的有效关节数和 status_counts，区分极线、低视差、负深度、骨长等拒绝。
3. 看 accepted_pairs、alternative_margins 与 identity_ambiguous，再讨论配对/ID，而不是只看最终有效点总数。
4. 同时比较误差、覆盖率、失败率和处理耗时；不要只报筛选后较容易的有效点误差。

HOT3D 虚拟分辨率/焦距目前在 `benchmarks/hot3d.py` 的 `HOT3DStereoGeometry.__init__(width=640,height=480,focal_px=160.)`，没有接到 stereo.yaml。评测二维身份分配的80px/10px参数在 `metrics.match_2d()` 签名中，也不是运行时左右关联阈值。这些入口均已加中文说明，不能假设改一个YAML会改变所有实验参数。

主要注释覆盖 core、stereo、calibration、detection、sources、benchmarks、storage 和 GUI worker 的线程调度；不改第三方官方模型代码，不改界面布局或可视化交互。
