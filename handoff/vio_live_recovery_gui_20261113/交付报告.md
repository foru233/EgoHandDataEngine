# EgoHandDataEngine VS030 v4 实时恢复 GUI 交付报告

本轮把已验证的 v4 恢复逻辑接入两个 GUI 的实际实时启动链路。客户 GUI 通过 `--live-recovery-candidate` 或 `run_live_recovery_candidate.bat` 打开隔离实验入口；研发 GUI 在实时 VIO 控制区选择 `v4 实时恢复实验版`。两个入口共用 `LiveRecoveryProfile`、`LiveVio`、`PipelineWorker`、质量门控、手部同帧关联和恢复状态机。

候选 Profile 固定绑定以下文件并在启动前校验 SHA-256：

- DLL：`handoff/vio_recovery_bridge_20261113/bin/egohand_vio_short_recovery_candidate.dll`，`d4e3d5f13341ff542111cee792ebac7aa160f976170330fd087fe8fca25c3158`。
- 恢复配置：`handoff/vio_recovery_bridge_v4_20261113/recovery_candidate.yaml`，`a96545804cf1db79399133dabf2311f73e589b7018f11899d4ced341e0a78df2`。
- 标定：`标定结果/2/data3-camchain-imucam-measured.yaml`，`ea0f6cc3db1881a3ea56b9e92a8f4ddf093d4bffb18e048f8f7a12056514e11d`。
- ORB 设置：`handoff/vio_architecture_execution_20261113/bootstrap_full_settings.yaml`，`8e7cf1ee8837696ff8720880ee6acacf3bdf26bb5697bd7dda5b44b284046517`。
- 实时质量配置：`configs/vio/live_quality.yaml`，`8af8beae71e519f3d759bf50671fd8317a347223d8ee4dde91934ad85693eb2e`。

候选配置使用每会话 `session_auto` 时序核验、全分辨率输入和现有约 2 秒 IMU 预测保护。预测输出与可信地图位姿分离；视觉恢复必须通过几何、身份、连续性和稳定窗口，超时建立独立 segment/新地图，不能把新旧地图直接拼接。原始录制仍由采集层独立保存，VIO 队列过载和 GUI 暂停不会静默替换原始数据。

启动后 GUI 日志显示实际子进程 PID、DLL 哈希和恢复配置哈希；配置或 DLL 内容变化会使持久进程重建。截图和软件启动证据见 [TEST_RESULTS.md](TEST_RESULTS.md)。

本轮没有设备运行证据，因此不声称真实 30 FPS、实机定位精度、长时间稳定性或恢复错误率改善。正式稳定版回退方式是关闭候选入口/把研发 GUI Profile 选回 `正式稳定版`；不需要修改 `active_bridges.json` 或替换正式 DLL。
