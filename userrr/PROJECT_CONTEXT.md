# 客户交付 GUI：项目背景与边界

本次背景来自聊天 `01a19f06-2b0c-7e22-a41d-61ffd49fa861`、原始 M01–M05 任务书及 2026-11-12 当前工作区。当前工作区存在大量既有未提交修改，本次在其基础上增量实施。

M01–M05 的核心是同步双目图像→手部二维检测→双目关联→三角测量→质量门控→左相机光学坐标下米制关节，服务机器人模仿学习与 VLA 数据生成。不能用单目 world landmarks、合成数据或检测成功代替真实米制测量和精度验收。

后续工作已接入 VS030、SDK 原码流录制、VIO 与世界轨迹。历史聊天报告的 v9 之后，本地部署清单已升级为 `egohand_vio_cheirality_v3.dll`；客户程序应复用部署选择器，不硬编码历史 DLL。

用户确认的实施决定：

- 客户壳层、入口及交付文档放在 userrr；允许 src 下共享层抽取和原 GUI 必要接线，保留原 run_gui.py。
- 算法为同一当前版本的纯双目视觉和双目＋IMU，默认后者。停止后才可切换，重建会话并清空旧轨迹。
- 原生录制按录制自身标定、时序快照重算，并支持已有结果回看；缺 IMU 仅允许纯视觉。普通 MP4 不作为完整 SLAM 输入。
- 原录制只读，客户端生成结果放在 userrr。

VIO 已基本追上此前纯视觉的平稳表现，尚无独立精度真值；不同版本、单轮纯视觉与多轮 VIO 的历史结果不是严格对照。快转、遮挡、长距离实机优势及长期精度仍待验证。不得把跟踪平稳表述为定位更准。

当前 IMU 时序使用逐会话核验，历史录制相位不一致，不能将 +97 ms 当通用固定真值。世界身份使用地图 epoch 和 world_frame_revision；变更时断开轨迹，不能连接不同世界原点。

深度为现有 StereoSGBM 的双目估计，受纹理、遮挡、极线方向和有效匹配范围限制；无效区域不得填成可信测量。手部局部相机坐标与 SLAM 世界坐标必须清楚区分。
