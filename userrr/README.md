# EgoHand 客户交付界面

在项目根目录 PowerShell 中运行（使用既有环境，无需新 GUI 框架）：

```powershell
# 客户界面，也可双击 userrr/run_client_gui.bat
.\.venv\Scripts\python.exe userrr/run_client_gui.py
# 合成演示，明确标注非实测，不运行定位
.\.venv\Scripts\python.exe userrr/run_client_gui.py --demo
# 原调试界面
.\.venv\Scripts\python.exe run_gui.py
```

客户界面为单页三列，图像按各自长宽比铺满格子，不做卡片边框：

- **左列（最大）**：一个三维视图，相机位姿与手部位姿画在同一场景里。左上角浮动开关可分别显示/隐藏**轨迹**、**相机**坐标轴、**手部**骨架，三个开关互相独立（关轨迹不会连带关相机），另有“复位视角”重新套到包围盒。手部使用当前位姿变换到 VIO 世界系；没有有效位姿时按相机原点显示，不冒充世界坐标。
- **中列（较小，纵向一列）**：**原始鱼眼左图**、**原始鱼眼右图**、**深度图**。原始鱼眼按设备输出原生像素显示，不裁剪、不加圆形遮罩、不改亮度；始终显示处理线程最新的那对原始帧（与当前处理帧不同号时在角标标出「第 N 帧」，不冒充同帧），只在显示副本上按格子宽度降采样。不做校正、不叠加识别。图像按原生比例铺满格子，不留黑边。
- **右列（较大）**：**校正左图**、**校正右图**，叠加左右手 21 点识别与轨迹编号，与三角化使用同一校正图像坐标。

窗口缩小时工具栏改为两行；中/右列宽度由图像长宽比和张数自动计算（三格列窄、两格列宽），窗口过窄时同比例收缩；每格图像按原生长宽比铺满，比例差在 2% 以内直接铺满以避免细黑边。深度由独立后台线程计算，校正器与 SGBM 匹配器跨帧复用，搜索窗口按 0.25 m 实际所需收窄（本机 96→32），标题栏显示本帧耗时与有效占比。深度范围 0.25–4 m 与管线同一口径，界面不另行放宽。详见 `UI_LAYOUT.md`。已有研发配置仍在原调试 GUI。

算法下拉框提供当前版本纯双目视觉和当前修复版双目＋IMU，默认后者。仅停止后可切换，启动时清空旧世界和显示历史。两者使用现行部署选择器及质量门控，未切换到历史旧 DLL；不承诺惯性模式定位更准。

新增“混合 · VIO优先 / 视觉回退”选项，只运行一个 IMU_STEREO 实例。混合模式允许视觉先建图，仅在 IMU 初始化、BA2 完成、惯性尺度最终确认且通过原质量门控后才显示为 VIO；BA2 之前保持同一实例的视觉引导来源，不把 IMU 初始化误认为惯性优化已完成。该选项使用单独构建的 visual_bootstrap DLL 和配置副本，不替换普通VIO默认库。它不是双开纯视觉SLAM。来源切换只在同一地图中断开显示线段、保留旧轨迹；仅地图身份变化或原生重置时清除不兼容的世界轨迹。详见 `HYBRID_MODE.md`。

## 录制与导入

1. 设备模式启动后可开始/停止录制，保存到 `userrr/recordings`，沿用原始码流归档和写盘错误处理。录制中不把协议时间语义称为已验证。
2. 点击“导入录制”选择项目原生会话目录，再启动。SDK 录制按录制自身快照重算；定位、手部和显示使用同一解码帧。输出放在 `userrr/sessions`；原始录制不修改。**混合模式对历史固定、未核验的 IMU 包头相位执行逐录制视觉/陀螺独立核验**，仅将核验得到的相位用于本次回放工作配置；不能核验则拒绝使用旧固定值，详情见 `HYBRID_MODE.md`。缺失或不一致的配置会明确报错，不静默换成当前配置。普通 MP4 不作为完整定位输入。
3. “查看已有结果”读取 `results/frames.jsonl`，滑条回看手部结果；含 `vio_pose` 的重算结果同时恢复截至所选帧的世界轨迹。该轻量回看目前不自动解码原始图像，双目和深度保持空白；需要完整图像时使用导入重算，或原调试 GUI 的已有结果回放。
4. 截图保存到 `userrr/screenshots`。

| 新增显示组件 | `userrr/delivery_views.py` | 按长宽比自适应的图像块、世界系手部叠加、三维视图浮层、深度后台任务 |

| 新增共享层 | `src/egohand/gui/shared/presentation.py` | 双目结果叠加、清帧、关联规则和状态模型 |

| 新增录制源 | `src/egohand/sources/sdk_recorded.py` | 复用 SDK HEVC 解码、配对和原标定 |
| 新增模式模型 | `src/egohand/vio/modes.py` | 模式校验和隔离子进程环境 |
| 扩展共享运行时 | `gui/workers.py`、`vio/live_runtime.py`、`vio/replay_runtime.py` | 显式传模式，纯视觉绕过 IMU 等待，SDK 同帧处理 |
| 新增验证 | `tests/test_gui_shared.py`、`tests/test_vio_sensor_modes.py`、`userrr/test_client_gui.py` | 共享、模式、客户生命周期回归 |
| 更新测试 | `tests/test_vendor_xdsdk.py` | 模拟对象接受新增模式接口 |
| 交付资料 | `PROJECT_CONTEXT.md`、`capture_preview.py`、`verify_recording.py`、日志和截图 | 背景与可复现验证 |

两套 GUI 共用 PipelineWorker、源工厂、worker 生命周期基础函数、ImageView、结果叠加策略及状态模型。客户世界视图直接复用 VioPanel 的世界身份、门控和轨迹更新逻辑，只隐藏研发控制。手部使用现有 SkeletonView、DisplaySmoother；深度复用 `vio/map_depth.py::StereoDepth`，后台约 0.7 秒节流并处理参考目与极线方向。未来修改这些公共模块会同时作用于两套 GUI。

VS030 实时和原生录制回放默认关闭裁剪补检（`configs/app.yaml` 的 `vs030_rescue_enabled: false`），每帧仍做左右全图检测；左右独立检测器并行完成后才进入下一帧，离线不跳帧。数据集继续使用 `configs/detector.yaml` 的原补检设置。处理 FPS 按最近 30 个完成间隔计算，不再将词典启动时间摊入整个会话；暂停或跳转会重置统计窗口。修改后需要停止并重新开始处理。

## 能力边界与验证

- 世界视图显示可获取的相机位姿和轨迹；不虚构稀疏地图、SLAM 精度或世界系手部。
- 手部骨架保持左相机光学坐标。深度是 0.25–4 m 双目估计，有效区之外为黑色，参考相机在标题中说明。
- 真实设备长跑、精度和快转遮挡优势尚未验收。本次硬件未实机连接验证。
- 部分历史 `recordings/map_scan_*` 快照的缩放与 ORB 内参不匹配，会被严格拒绝。本次没有修改这些历史数据。
- 真正 Qt/OpenGL 截图与证据见 `screenshots/`，合成截图不冒充设备实测。

测试与真实录制结果见 `TEST_REPORT.md`。
